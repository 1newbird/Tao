# Tao 总纲与路线图

本文档是 Tao 的产品与技术总纲。它规定 Tao 如何把 Pi 作为 Agent Runtime 装配进桌面产品，以及后续功能的先后顺序。

## 一、产品定位

```text
Tao = 桌面产品壳 + Tao Runtime 装配层 + Pi Agent 内核
```

Pi 负责 Agent loop、Session、上下文压缩、Provider、Model、Skill、Extension 和工具机制。Tao 负责中文产品界面、运行状态、配置工作台、权限边界和桌面交互。

Tao 不复制 Pi 已经实现的内核能力。新增能力必须先查阅 [Pi能力清单与映射.md](./Pi能力清单与映射.md)，优先使用 Pi 的 RPC、SDK、SessionManager 或 Extension 接口。

## 二、目标产品结构

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ Tao 工作区   │ 对话主区域                   │ 运行检查器       │
│              │                              │                  │
│ 新建会话     │ 当前模型与思考模式           │ Runtime 状态     │
│ 历史会话     │ 消息、思考、流式输出         │ Session 信息     │
│ 搜索、置顶   │ 停止、调整、回答后继续       │ 上下文与队列     │
│ 定制入口     │ 输入框                       │ 工作区、变更摘要 │
└──────────────┴──────────────────────────────┴──────────────────┘
```

左栏和右栏都可以收起。右栏显示 Runtime、当前会话、工作区、文件变更摘要、diff 摘要和验证状态；它不显示终端输出、工具原始调用或工具时间线。Pi 工具事件驱动聊天区中的当前状态与可折叠执行摘要，权限请求在具备产品级授权设计后再接入。

## 三、分阶段路线

### 阶段一：基础对话与启动体验

目标是让 Tao 达到 Codex/Claude Code 类产品的基础使用顺畅度。

- 打开 Tao 后先显示完整界面，不等待 Pi 预热完成。
- 当前会话后台预热，明确显示“准备中/已就绪/失败”。
- 历史消息先展示，Session 恢复在后台执行。
- Tao 启动后保持一个 Node Runtime，由它托管多个独立 AgentSession，保证多会话并发。
- 保留停止、steer、follow_up、流式思考和回答。
- 显示 Pi 准备、首个输出和完整回答耗时。
- 修复异常中断恢复和会话投影对账。

验收标准：打开窗口后约 1 秒内看到主界面；切换会话不阻塞其他会话；两个会话可以同时生成。

当前实现状态：

- 应用状态和模型目录已拆分加载，不再使用一个 `Promise.all` 阻塞主界面。
- Tao 配置与历史加载完成后立即显示聊天界面，模型目录和当前 Session 在后台继续准备。
- 顶部显示“读取配置/准备当前会话/恢复会话/已就绪/失败”。
- Pi 准备、首次输出和完整回答耗时保留在会话运行状态中，流式消息收尾后仍可在右侧查看。

### 阶段二：左右侧栏与运行检查器

- 左栏：新建、历史、搜索、置顶、删除、运行标志和“定制”入口。
- 右栏：Runtime 状态、当前 Session、模型、思考模式、上下文使用量、队列和耗时。
- 统一折叠、快捷键和窗口宽度行为。
- 右栏预留工作区、文件变更摘要、diff 摘要、验证状态和权限入口；不预留工具日志或终端输出面板。

当前实现状态：左侧会话栏支持收起和恢复、按标题/工作区搜索、置顶、重命名、删除确认和后台未读标志；右侧运行信息已经改为独立第三栏，打开时重新分配主区域宽度，不再覆盖聊天内容。已提供 `Ctrl/Cmd+K` 新建、`Ctrl/Cmd+P` 聚焦搜索、`Ctrl/Cmd+B` 收起侧栏和 `Esc` 停止生成。右侧仍只显示 Runtime/Session/工作区摘要，不作为工具日志面板。

### 阶段三：Tao Runtime 事件模型

React 不直接依赖 Pi 原始 JSON 事件。Rust/Tauri 建立稳定的 Tao Runtime 事件层：

```text
Tao Runtime Event
  ├─ runtime      启动、ready、健康、关闭
  ├─ session      创建、恢复、切换、分支、压缩
  ├─ turn         开始、结束、停止、重试
  ├─ message      用户、思考、正文、错误
  ├─ queue        steer、follow_up、队列变化
  ├─ tool         工具开始、更新、结束
  ├─ context      使用量、窗口、压缩阈值
  ├─ permission   权限请求、批准、拒绝
  └─ error        可恢复和不可恢复错误
```

Pi RPC 事件由 Runtime 转换成产品事件；UI 只依赖 Tao 事件和状态，不绑定 Pi 内部字段。工具事件只归约为当前动作，例如“正在读取 src/App.tsx”“正在修改 src/App.tsx”“正在根据读取结果整理回答”；原始参数、stdout、文件正文和完整工具结果不会跨 Node → Rust → React 边界。

### 阶段四：Pi 能力接入与映射

完成 Pi 能力清单、版本核对和接入状态标记。重点包括：

- SessionManager、Session 树、分支和 `switch_session`。
- Agent loop、上下文压缩和 compaction hooks。
- Prompt、Context 文件、Skill、Extension 和自定义命令。
- Provider、Model、思考级别和认证。
- Pi 默认工具、工具事件和后续权限边界。
- RPC 控制、流式事件和错误恢复。

这一阶段只做能力理解、映射和最小桥接，不直接开放任意代码执行。

### 阶段五：Prompt/Context 定制工作台

左栏“定制”进入配置工作台，第一版以结构化配置为主：

- 系统提示词片段。
- 会话开始提示词。
- 每轮前置提示词。
- 用户级、项目级和条件上下文。
- 上下文注入顺序和启用条件。
- 自动摘要和压缩策略。
- 输入预处理和分类策略。

工作台保存为 `.tao/runtime/` 下的版本化配置，由 Runtime 转换为 Pi 的 Extension/Resource 配置。第一版不提供任意 TypeScript 扩展执行器。

### 阶段六：工具、权限和沙盒

- 工具事件继续归约为聊天区当前状态与可折叠执行摘要；工具结果不跨 Runtime 边界。
- 右侧显示文件变更摘要、diff 摘要和验证状态，不显示终端输出或工具时间线。
- Tao 定义工作目录、文件范围、命令确认和网络访问策略。
- 权限和沙盒是 Tao 产品层能力，不因 Pi 已有工具机制而默认开放。

### 阶段七：Runtime 优化与正式发布

- 评估单进程 `switch_session`、并发进程池和空闲进程复用。
- [x] Windows x64 第一版将内置 Node、Pi 源码/依赖和 Tao Runtime 打包为 Tauri resources，并生成 MSI 安装包。
- [ ] 继续评估资源裁剪、NSIS 压缩耗时、代码签名和其他平台构建。
- 增加崩溃恢复、日志、诊断和版本迁移。

## 四、关键架构决策

1. Pi 能力先清单化，再接入 UI。
2. React 不直接绑定 Pi 原始事件。
3. Runtime 负责 Pi 进程、Session、事件、配置和扩展装配。
4. 当前阶段使用单一 Node Runtime 和多个独立 AgentSession 保证并发；不使用会中止当前会话的 `switch_session` 实现产品切换。
5. `.tao` 是用户数据、Runtime 配置和扩展资源的统一根目录。
6. 权限、工具和沙盒必须经过 Tao 产品层设计。
# Tao Runtime 事件信封（v1）

Rust/Tauri 对 Pi RPC 事件做统一映射，前端只订阅 `tao-runtime-event`。事件包含 `version`、`category`、`event`、会话 ID、请求 ID、可选文本和耗时。消息增量、回合、队列、运行状态、错误和耗时指标均使用统一信封；后续新增 Pi 能力先扩展映射，不让 React 直接依赖 Pi 原始字段。

## Prompt/Context 工作台第一版

Tao 首版定制入口使用 Pi 原生 `--system-prompt` 和 `--append-system-prompt`，配置保存到 `.tao/runtime/profile.json`。当前支持启用开关、追加/替换系统提示词和每个会话的附加提示词；保存后重建空闲 Runtime，会话历史仍由 Pi session JSONL 保留。扩展脚本、Skill、工具权限和沙盒暂不在本版工作台中开放。

定制入口已经从弹窗升级为独立主页面。左侧产品导航、中央页面容器、右侧上下文检查器构成稳定壳层；后续 Prompt、Context、Session、Agent、Skill 和 Extension 均在此壳层内逐项接入，不再向聊天页面堆叠临时弹窗。工具选择和 Agent loop 不属于 Tao 定制项。

## 当前 UI 第一批交互能力

- 助手消息支持基础 Markdown：标题、段落、列表、引用、链接、行内代码和 fenced code block。
- 助手消息和代码块提供复制入口；复制内容只取纯文本，不包含界面状态。
- 后台会话在回答完成或失败后显示未读标志，进入该会话后清除。
- Runtime 检查器提供“重启 Runtime”和“重新连接当前会话”，仅在没有会话生成/预热任务时启用。“重新连接当前会话”只负责确认或恢复当前 Pi AgentSession，不创建新消息、不清空上下文、不触发重新生成。
- 这些能力属于 Tao 展示和生命周期层，不改变 Pi 的默认工具、Agent loop、重试或上下文行为。

## 第二阶段：会话管理体验（当前范围）

第二阶段只改善 Tao 壳层的使用效率，不新增 Agent 能力，也不改变 Pi 的会话语义：

- 左侧搜索匹配会话标题、工作区名称、工作区路径和已保存消息正文。
- 左侧会话栏与右侧 Runtime 检查器支持拖拽调整宽度，范围分别为 220–380px 和 280–480px；布局偏好保存到浏览器壳层的 `localStorage`，不写入 Pi 配置。
- 当前会话可以从聊天顶部导出为 Markdown、JSON 或纯文本。导出内容只来自 Tao 已保存的会话消息，不包含工具原始参数、stdout、完整工具结果或 UI 状态控件。
- 本阶段明确不做“重新生成”、历史消息编辑、Pi 分支、单条消息删除和复杂会话树；这些功能会改变会话事实来源或语义，不能作为简单 UI 补丁加入。

# 主任务可靠性验证 · 2026-10-19

## 改动范围

发送消息先将任务编号、内容指纹和用户消息原子保存，再返回启动回执。Node 持续执行，Rust 接收最终结果后重新加载最新会话、归档消息并发布终态；React 通过事件与状态补查恢复显示。同一会话有活动任务或未保存结果时阻止新任务，不同会话可并行。

重复提交同一编号和相同内容返回既有记录；编号用于不同内容时拒绝。停止和追加均绑定原任务编号，迟到控制不会命中下一轮。结果保存失败保留已经计算的消息，重试只提交磁盘，不执行模型和工具。退出停止新派发并回收后台，重启将遗留记录标为中断，不自动续跑。

## 浏览器模拟交互

运行 `npm.cmd run preview:ui`，打开 `http://127.0.0.1:1432/__ui_preview?scenario=showcase`。以下 `case` 仅在开发预览桥中生效，不进入正式应用：

| case | 已观察结果 |
|---|---|
| `fast` | 完成事件早于延迟启动回执，保留一组消息，未回到运行中 |
| `lost-receipt` | 回执异常后由任务记录确认，保留一组消息 |
| `missed-completion` | 没有最终事件，轮询补回结果并恢复可用状态 |
| `uncertain` | 两次回执失败且状态暂不可查时，显示待核对，禁止新执行；连接恢复后显示已有结果 |
| `save-failed` | 显示结果待保存，隐藏停止/追加和加载动画；点击重试保存恢复一份回答 |
| `late-completion` | 停止第一轮后开始第二轮，旧终态通知未清除第二轮；两个会话并发，停止一个后另一个仍运行 |
| `restore` | 加载已有活动记录可恢复运行状态，结束后显示一份回答 |
| `rejected` | 明确未接收时恢复原输入，不遗留生成状态或乐观消息 |

界面记录保存在本地忽略目录 `.tao-ui-qa/runs-*.jpg`；运行中的截图只证明对应模拟状态，不代表实际桌面进程或模型行为。

## 仍需原生验收

使用项目环境执行 `npm.cmd run tauri dev`，分别核对：

1. 实际模型生成期间切换会话；向上阅读、复制、追加和停止正常。
2. 生成期间在设置中停止或重启 Runtime；旧请求显示中断或停止，不自动重发。
3. 生成期间退出 Tao，后台 Node 及命令子进程回收；重开后遗留记录标为中断，不自动执行。
4. 若模拟磁盘不可写，恢复写权限后“重试保存”只归档结果，不再调用工具；保存前不要退出。
5. 协作成员查看、人工介入和独立窗口仍可用；打开查看页不产生新执行。
6. 用户确认出包后再构建 MSI，验收安装升级、任务栏/快捷方式图标、发布资源和干净环境运行。

本批没有打包、安装或发布新 MSI，也未宣称支持中断任务自动续跑或完整操作系统沙盒。

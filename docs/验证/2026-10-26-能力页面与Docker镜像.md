# 能力页面与 Docker 镜像验收

日期：2026-10-26。基线为已发布的 0.2.0，本记录仅描述开发源码增量；没有生成 MSI、提交、推送或发布。

## 实现范围

- “联网检索”“外部服务 · MCP”“技能 · Skills”独立配置页；MCP 连接与工具详情、技能添加与技术信息按需展开。
- 搜索和网页读取分别显示启用、配置、凭据与权限状态；搜索本页测试成功/失败不会被当作长期可用性。检查配置不发网络请求，不返回凭据值。
- 聊天“能力”按持久化会话快照检查联网状态；MCP/Skills 展示配置摘要，实际连接与技能加载分别以调用及会话技能清单为准。
- `tao-runtime:0.1.0` 配方、命令行和设置页准备入口，使用随包 Runtime 构建并验证；已有组合显式选择的镜像不变。

## 自动检查

- 能力状态专项、权限与本机执行回归通过；覆盖无凭据、拒绝读取未授权凭据、禁止联网、后端默认值、域名限制、私网接口及快照独立性。
- agents 脚本内的联网、MCP、文档、协作、上下文、Skills 和安装专项通过。完整脚本的 Runtime 阶段在受限测试环境遇到 Node `uv_os_get_passwd ENOMEM`，随后使用随包 Node 22 在环境外单独运行通过；Rust 24 项另行运行通过。
- 源码和最终随包资源分别通过完整 Runtime + 合成模型/搜索/MCP/GitHub 调用链。此次增加配置状态检查，并确认检查不触发模型请求。
- `npm run check`、最终 `npm run build`、`npm run test:ui` 通过；主前端块约 492 kB，无超过 500 kB 的构建警告。UI 自动检查包含 216 种面板宽度组合及 Markdown/流式渲染。
- `npm run tao:prepare`、`npm run tao:verify` 通过：固定基础镜像摘要与配方哈希、内置 Node 22.23.3、原生组件、10 份许可、随包 PDF/DOCX 解析、普通及 Windows 扩展路径 ready/ping。资源合计约 355.2 MiB。
- `git diff --check` 通过；工作区原有改动保留。

## 真实 Docker 验收

本机 Docker Desktop Linux/amd64 构建成功。基础镜像固定为 `node:22-bookworm-slim@sha256:c3de60bf2f9dd0ac6370e6117950ff62d6e339527e7472301c9c78a017978392`。

- 成品 image ID：`sha256:17ac29203177b8318404dceb25d1c255421097e771ebd72565175b0adc0d92b3`。
- 本地镜像大小 909,143,077 字节（约 867 MiB）；不等同于下载压缩体积，不包含在 Tao 安装资源内。
- Node 22.23.3 / npm 10.9.9、Python 3.11.2 / pip 23.0.1、Git 2.39.5、ripgrep 13、jq 1.6、curl 7.88.1、GCC 12.2、Make 4.3、zip/unzip 检查通过。
- 非 root UID/GID 1000、断网、只读根目录、资源上限下的工具和 UTF-8 验收通过；拒绝写系统目录。
- 首次工具自检尝试执行 `/tmp` 的 C 产物，被既有 noexec 边界阻止；改为在那里仅编译对象文件，未放宽隔离。随后通过工作区内 C 编译/跨容器执行以及 Python venv 跨容器复用测试。
- Docker 执行回归覆盖文件读写、只读工作区、工作区外路径、网络/凭据限制、目录链接、取消和缺失镜像错误。本批验收临时容器和临时镜像标签均已清理，保留版本镜像及 Docker 构建缓存。

镜像准备先构建临时标签并验收，再更新版本标签。公共仓库、成品 digest 分发、自动升级与漏洞审查流程待后续设计；Debian 软件包安装来自当时的软件源，不承诺重复构建逐字节相同。详见[镜像维护说明](../../src-tauri/runtime/docker/README.md)。

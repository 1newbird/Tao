## 路径根因

Tauri 可传入 `\\?\D:\Project`。SDK 将相对文件名解析为同命名空间的绝对路径，而执行接口将 canonical 工作区规范化为 `D:\Project`。在两者之间直接做 `path.relative`，Windows 返回绝对结果，导致工作区内目标被误判越界。

在执行接口的路径映射入口先统一 Windows 命名空间，再解析与检查包含关系。真实越界、其他项目和 UNC 路径不因此获得权限。SDK 验证使用带前缀的工作区，以及相对写入、编辑、读取、目录、内容搜索和文件搜索；路径专项已通过。

真实脚本验收又暴露了两个启动兼容点，均保留了失败记录：

1. fork 能创建管道，但脚本子进程退出 1；捕获 stderr 后发现 Node 的 JS 模块解析在带扩展前缀的当前目录中尝试 `lstat('D:')`。启动器继续使用 canonical 路径做 ACL 和包含检查，仅将传给 `CreateProcessW` 的当前目录转换为普通 DOS 路径；fork 随后通过。
2. npm 入口位于 Tao 私有缓存，模块解析需要读取其祖先目录元数据。启动器原先只准备工作区祖先，导致 `lstat(tao-home)` 被拒。现对已授权运行时 / 临时目录的祖先也加入每次执行独有 SID 的非继承元数据授权，不授予列目录、内容或写入；结束后精确撤销。

## Node 构建

- 固定官方 Node 22.23.3 源码，归档 SHA-256 为 `bd97093e1a1e9243338950c174a693a64d4e0926a9c6ce259962bc58d5e96909`。
- 合入 [libuv 2cadaa40167050baf7c6905ac897e6fb57afb2c6](https://github.com/libuv/libuv/commit/2cadaa40167050baf7c6905ac897e6fb57afb2c6) 的运行时修改，只在 AppContainer 中给自动子进程管道添加 `LOCAL` 命名空间。
- 上游回溯背景见 [Node #66374](https://github.com/nodejs/node/issues/66374)。本批查询正式发行列表尚未含该修复，未直接把“升级 Node”当作解决方案。
- `scripts/build-sandbox-node.mjs` 在项目缓存目录构建；系统 Node 和全局 npm 不变。版本、源码、补丁、编译器、参数及每个发行文件的 SHA-256 进入构建清单。
- 发布资源使用同一份私有 Node 作为 Runtime 和工具 Node，附带 npm/npx，保留官方源码及包内许可。开发工具使用经过校验的私有缓存；缺失或校验失败时拒绝运行，不回退系统未修复的 Node。

## 保留边界

补丁不开放网络、不扩大文件权限，不授予任意应用自定义命名管道，也不让普通构建命令突破 120 秒 / 1 GB Job 限额。联网依赖安装、长驻开发服务、超过授权条目上限或包含目录链接的项目仍需分别处理。Windows 10、跨用户、真实重启和任意 Windows 程序兼容尚未验收。本批不构建 MSI、不推送或发布。

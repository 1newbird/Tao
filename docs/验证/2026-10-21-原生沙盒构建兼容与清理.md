# Windows 原生沙盒构建兼容与清理

日期：2026-10-21。测试系统为当前 Windows 11 23H2 x64。最低兼容目标仍为 Windows 10 x64，未取得 Windows 10 真机或虚拟机验收结果。本批没有生成 MSI、变更版本号或推送发布。

## 修复与取舍

前一轮 Node 管道修复后，esbuild 0.28.2 仍会沿工作区路径枚举宿主祖先，遇到隔离拒绝后终止，详见其 [resolver 源码](https://github.com/evanw/esbuild/blob/v0.28.2/internal/resolver/resolver.go)。这与应用自身 MSI 构建不同。

本批让 PowerShell 命令的当前目录成为临时盘符根目录。盘符映射到原工作区，普通子进程沿用当前目录，esbuild 无须枚举宿主父目录。依赖预先位于工作区的 npm、TypeScript、esbuild 和 Vite 均保持原始实现；不为每种构建工具复制或修改一份源码，也不增加目录列举权限。

映射采用 Windows 的 DOS 设备命名机制；会话作用域和从 Z: 向前分配的依据见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/fileio/defining-an-ms-dos-device-name)。它对当前登录会话可见，**不是进程私有文件系统或安全边界**。本批还验证过进程私有 DeviceMap；普通 Node 子进程未继承该映射，故未保留该实现。声明依据与 ABI 可对照 [System Informer phnt](https://github.com/winsiderss/phnt/blob/master/ntobapi.h)，产品中只保留必要 API 声明。

## 权限与生命周期检查

- 唯一 AppContainer SID 继续控制文件内容权限，网络 capability 不变。映射对象只给创建者及本次 package SID 必要查询权限，不向其他 AppContainer 身份开放。
- QueryDosDevice 检查占用，NtCreateSymbolicLinkObject 原子创建；碰撞跳过，不带 OPENIF 或 PERMANENT，不覆盖、修改或删除已有映射。Z: 至 E: 均不可用时明确报错，无本机回退。
- 链接目标通过已打开目录句柄取得 NT 设备路径；目录句柄不共享删除，执行中不能改名或替换工作区根目录。此限制不等同于锁住所有子文件；成员共享文件的冲突仍需业务协调。
- 映射生命周期由持有的 NT 链接句柄控制，正常/失败路径通过 RAII 关闭，helper 被强制终止时系统关闭句柄。Job 继续回收后代；ACL/profile 恢复沿用已有日志与唯一 SID 校验，没有再建第二套清理日志。
- 修复兼容探测将会话盘符误认为全局设备的问题；临时映射和其他仅会话可见的盘符不再引起错误的管理员初始化请求。
- 内部 `TAO_SANDBOX_WORKSPACE` 由 helper 设置，列为保留变量。NT 对象声明与打开函数集中到 `nt.rs`，兼容授权和工作区映射共用；未保留失败原型和重复对象声明。
- 审查新增根目录替换用例，修复前确实读到了另一个合成目录的测试文件，见 [失败记录](../../.tao-release-cache/windows-executor-lab/drive-run-6b51lk/report.json)。修复后，在 canonicalize 前检查原路径及祖先，拒绝解析结果重定向；ACL 读取/更新统一改用 `FILE_FLAG_OPEN_REPARSE_POINT` 打开的已验证句柄，使用 GetSecurityInfo / SetSecurityInfo，不再次按名称跟随到链接目标。工作区在扫描、授权和执行前即固定，清理同样拒绝跟随链接。
- 文件 worker 和普通结构化程序仍用原工作区路径。命令输出提示映射与释放时机，后续调用应使用原路径或相对路径；不会把命令输出正文全局替换成另一组路径。

## 补齐发布依赖

PE 导入表审查发现原辅助组件动态导入 VCRUNTIME140.dll，当前开发机具备该 DLL 不能代表干净电脑可运行。辅助组件构建现固定 `+crt-static`，同时保留并恢复调用方原来的 Rust flags；不要求安装用户额外安装 VC 运行库。最终辅助组件仅有 7 项 Windows 系统 DLL 导入；随包 Node 也没有外部 VC 运行库依赖。

发布验证通过独立的 PE 普通/延迟导入表解析检查两份程序，不依赖开发机的 dumpbin。实际旧动态构建已被校验拒绝，静态构建通过；与本机 dumpbin 输出交叉核对。最终辅助组件 SHA-256：`5d86da094dfeb9d40124df2ae86ff0518fb5dde701326339fea638dae4f1db05`。

另修复 PowerShell 7 `ConvertFrom-Json` 将日期字符串转成日期对象、再次写出时改变 Node 不可变构建记录的问题。独立 helper 构建只用 Node 更新自己的哈希，不重写其他构建字段；被改写的测试清单已从原 Node BUILD-MANIFEST 恢复。PowerShell 5/7 两个构建入口实际运行后，完整 Node 记录保持一致，辅助组件哈希不变。

14 项核心与 12 项构建在句柄授权修复后执行；随后只变更辅助组件 CRT 链接方式，使用最终静态程序再次完成 5 项安全/生命周期及随包 SDK 联合验收。空请求环境在启动前明确拒绝。资源合计约 282.7 MiB，仍只携带一套 Node/npm，没有添加编译器、Docker 或独立的 esbuild/Vite 运行时副本。这是未压缩资源体积，未生成新的 MSI。

并发用例同时运行两个只读工作区：各自读到自己的数据，对方物理路径及对方临时盘符均不可读，宿主父目录与磁盘根目录不可枚举；占用盘符未被覆盖。执行中改名工作区被拒绝。所有路径恢复后的主机盘符列表与初始一致。

崩溃用例在嵌套 Node 已启动后强制终止 helper：后代延迟写入未发生，临时盘符消失；预期残留的一份 ACL 日志经恢复清理后归零。取消和 CreateProcess 启动失败也没有留下盘符或授权日志。

最终汇总审计还找到前期失败测试控制器退出所留的两份独立日志，均位于 `drive-run-uw6Z1z`；通过最终执行器恢复清理，活动租约跳过数为 0。再次检查测试目录未处理日志为 0，登录会话盘符仅 C:、D:。这也验证了异常退出后仍需重放日志，不能把“进程/盘符已关闭”当成“ACL 已清理”。

首轮新增并发测试因 PowerShell 5 改写内嵌 JavaScript 双引号而失败/等待超时；修正测试传参后通过。没有为测试放宽目录或网络权限。此前原型与 10/11 报告保留其历史结果，不改成通过。

补测中的“仅拒绝目录写共享就能阻止元数据修改”假设未通过正反对照，未作为安全机制保留；最终授权依赖不跟随链接的句柄，根目录句柄用于阻止改名/删除。整个登录会话盘符清单校验还会受到其他测试临时盘符的影响，因此生命周期套件独立顺序运行，未将并发套件造成的清单变化当成产品残留。上述失败用例均保留原始报告。

复现（先初始化测试目录祖先，实际用户权限运行）：

```powershell
node scripts/test-windows-executor.mjs
node scripts/test-windows-node.mjs
node scripts/test-windows-workspace-drive.mjs
```

这三个命令顺序运行；最后一项会比较当前登录会话的完整盘符清单，运行期间不要同时启动其他原生命令测试。

## 剩余验收与限制

- Windows 10、跨用户、真实桌面 UAC 取消/重启恢复与长时间压力待验收；不以这批 Windows 11 测试替代。
- 命令仍离线且有 120 秒与 Job 资源限制；没有测试 npm 联网安装或常驻开发服务器。
- 硬编码宿主绝对路径、越出所选项目的 monorepo 配置/依赖仍可能受限；应选择包含完整依赖的工作区，或明确选择本机 / Docker。
- 已有 reparse point、超过 10000 项的授权树、空闲盘符不足仍会拒绝执行；普通 AppContainer 公开的系统资源可能可读，映射不隐藏整台磁盘。
- 硬链接、运行中子目录元数据变更、盘符耗尽/热插拔的进一步对抗与压力验收未覆盖；不将根目录替换回归当成所有文件系统竞争条件已经穷尽。
- 包内资源及 SDK 联合回归通过；真实桌面与真实模型由用户继续验收。安装包编译与发布前继续先征求用户确认。

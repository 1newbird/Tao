# 2026-10-20 执行边界、Docker 与压缩策略验收

## 本批范围

开发源码新增统一执行接口、组合级文件 / 网络 / 凭据边界、可选的 Docker 工具后端及压缩策略。旧组合默认本机执行、沿用 Runtime 压缩设置。已有会话继续使用快照，保存组合不追改正在运行的任务；父子执行限制取交集。

当前尚未生成新 MSI，已有 v0.1.4 安装包不包含这些修改。本批使用隔离配置与本地模拟模型，不读取用户 API Key，不调用付费模型，不修改真实用户会话。

## 验收环境

- Windows x64，宿主 Node 24.19.0；SDK 回归使用发布资源内 Node 22.19.0。
- 本机 Docker Linux 引擎 29.8.0；官方 `node:22-bookworm-slim` 镜像内 Node 22.23.3。
- 镜像摘要：`sha256:c3de60bf2f9dd0ac6370e6117950ff62d6e339527e7472301c9c78a017978392`。
- 所有容器测试只挂载仓库内临时工作区；测试结束临时资料清理，按 `tao.sandbox=true` 标签查询没有遗留容器。不修改其他项目容器或 Docker 存储配置。

## 回归中发现并修复

1. Docker 未启用交互输入时 worker 无法收到请求；补齐 `--interactive`，真实文件读写通过。
2. Windows 自定义命令的引号与原 shell 行为有差异；恢复 CMD 的参数传递语义，原超时与自定义命令用例通过。
3. 受限组合的审核钩子错误阻止合法容器工具；修正审核与直接用户 shell 的入口，合法工具在受控后端执行。
4. Linux `/workspace` 路径被 Windows 宿主解析到错误磁盘位置；统一路径映射后再审核，并在容器内做实际路径校验。
5. 执行和压缩规则最初只校验旧配置保存接口；迁入通用规范化入口，组合保存 / 导入 / 读取均共用；增加目录版本、快照与非法名单回归。
6. Docker 命令沿用 SDK 的流式输出、截断和退出码处理；压缩失败保留实际原因，不以取消或成功掩盖失败。

## 当前边界与后续验收

- Docker 是可选依赖，需要本机服务与镜像；不支持远程 Docker 或 Windows 容器，不自动安装 Docker。
- 工具按操作建立临时容器，工作区可直接写入原文件；不是事务回滚，也没有逐成员文件副本。
- Docker 文件搜索有明确上限，不解析 `.gitignore`，正则使用 JavaScript；本机工具保留原搜索实现。
- HTTP 在 Tao 宿主受控代理中执行；设置域名名单时容器命令保持断网。任意进程的域名代理尚未实现。
- 任意扩展是可信宿主代码，受限组合拒绝加载；桌面程序、模型 SDK 和整台电脑不在工具容器里。
- 压缩沿用同一内核的摘要与归档；独立摘要查看、逐轮完整追踪、团队 token / 费用硬预算仍待开发。
- 仍需原生桌面、真实模型长对话、Docker 中断与新 MSI 安装升级验收；出包前先征得用户确认。

操作入口、准备脚本和参数说明见 [权限执行沙盒与压缩策略](../项目手册/13-权限执行沙盒与压缩策略.md)。

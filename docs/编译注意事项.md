# 编译注意事项

这份说明只写 Tao 本地开发里最容易踩坑的编译、清理和运行问题。

## 1. 启动开发环境

Windows 下优先用：

```powershell
npm.cmd run tauri dev
```

如果只想看前端页面，单独跑：

```powershell
npm.cmd run dev
```

## 2. 端口占用

`npm.cmd run tauri dev` 默认会带起 Vite，常用端口是 `1420`。

如果报错：

```text
Port 1420 is already in use
```

说明这个端口已经被别的 Tao / Vite 进程占着了，不是代码本身编译失败。

处理方式：

1. 先找出旧进程。
2. 结束旧的 `npm run dev` 或 `vite`。
3. 再重新启动 `npm.cmd run tauri dev`。

## 3. `cargo clean` 是否可用

可以用：

```powershell
cargo clean --manifest-path src-tauri/Cargo.toml
```

它只会清理 `src-tauri/target` 里的 Rust 构建产物，不会删源码、不会删 `.tao`，也不会动 `vendor/pi`。

适合在下面几种场景用：

- Rust 构建状态乱了。
- 想释放磁盘空间。
- 想强制重新编译。

不适合每次启动前都执行。

## 4. 为什么项目目录会变大

Tao 目录变大，主要不是因为业务代码多，而是因为 Rust 的 debug 构建产物会很大。

常见大头是：

- `src-tauri/target/debug`
- `src-tauri/target/debug/deps`
- `src-tauri/target/debug/incremental`

这里面会包含 `.rlib`、`.lib`、`.pdb`、`.rmeta` 之类的编译缓存和符号文件。

也就是说，几 GB 大多是“编译结果”，不是“手写代码”。

## 5. 重新编译会发生什么

`npm.cmd run tauri dev` 过程中：

- 前端会由 Vite 处理。
- Rust 后端会由 Cargo 编译。
- 第一次或改动较大时会慢一些。
- 之后再启动，通常会复用已有增量编译缓存。

所以磁盘会持续占用一些空间，但不是每次启动都从零开始堆一遍。

## 6. 依赖安装位置

Tao 的开发依赖和 Pi 副本依赖分开管理：

- Tao：`<Tao 项目根目录>`
- Pi 副本：`<Tao 项目根目录>\vendor\pi`

不要修改原始 Pi 源码目录，只在 Tao 里做集成。

## 7. 当前开发约定

- 命令优先用 `npm.cmd`。
- 需要检查时用 `npm.cmd run check`。
- 需要开发运行时用 `npm.cmd run tauri dev`。
- 清理 Rust 构建缓存时用 `cargo clean --manifest-path src-tauri/Cargo.toml`。
- 如果 `vendor/pi/node_modules/.bin/tsx.cmd` 不存在，先在 `vendor/pi` 下执行 `npm.cmd install --ignore-scripts`。

## 8. 生成 Windows x64 发布安装包

当前发布目标先支持 Windows x64。发布命令会自动准备：

- 内置 Node.js 22.19.0；
- Tao Runtime；
- `vendor/pi` 的源码、模型数据和 Node 依赖；
- Tauri Windows x64 安装资源。

执行：

```powershell
npm.cmd run tao:release
```

发布时可以用参数一键更新版本号，推荐在 npm 命令中使用 `--` 分隔额外参数：

```powershell
npm.cmd run tao:release -- 2.1
```

这会把版本规范化为 `2.1.0`，同步更新 `package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 和 `src-tauri/Cargo.lock`，然后生成带版本号的 MSI。也可以使用完整版本号，例如 `2.1.0` 或 `2.1.0-beta.1`。

发布脚本内部直接调用 Node.js 执行准备脚本和 Tauri CLI，不依赖 Windows 的 `npm.cmd` 或 `tauri.cmd` 子进程包装器。因此清理 Rust 缓存后不需要先运行 `npm.cmd run dev` 或 `npm.cmd run tauri dev`，可以直接发布。

生成结果位于：

```text
src-tauri/target/x86_64-pc-windows-msvc/release/bundle/
```

当前默认会生成 MSI 安装包。发布准备过程会将临时资源写入
`src-tauri/resources`，将 Node 压缩包缓存到 `.tao-release-cache`；这两个目录都不应提交到源码仓库。

正式安装版不依赖目标电脑安装 Node.js，也不依赖目标电脑存在 Tao 源码目录。用户配置和会话数据仍然保存在目标电脑用户目录下的 `.tao`。

当前限制：

- 只构建 Windows x64；
- 首次发布准备需要网络下载 Node.js，之后会复用本地缓存；
- `vendor/pi/node_modules` 会被复制进安装资源，因此安装包会明显大于开发源码包；
- 仍需要在没有 Node.js 和没有 Tao 源码的 Windows x64 电脑上完成一次干净安装验证。

当前默认发布命令只生成 MSI，以避免大型 Pi 资源在 NSIS 压缩阶段触发超时：

```powershell
npm.cmd run tao:release
```

如果后续需要单独尝试 NSIS，可以执行：

```powershell
npm.cmd run tao:release:nsis
```

NSIS 也可以带版本参数：

```powershell
npm.cmd run tao:release:nsis -- 2.1
```

不传版本参数时使用当前项目版本。重复生成同一版本时，输出目录中同名安装包会被覆盖；只改安装包文件名不会改变安装包内部版本。

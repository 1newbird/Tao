# 权限、执行沙盒与压缩策略

本页对应 0.3.0，最后核对于 2026-10-26，包含 Tao 基础镜像和准备入口。发布与验收见 [0.3.0 验收记录](../验证/2026-10-26-0.3.0发布验收.md)，原生后端历史验收见 [0.2.0 记录](../验证/2026-10-21-0.2.0发布验收.md)，当前待办见 [开发 TODO](../开发TODO.md)。Windows 原生后端继续标注预览。

## 配置入口

在“定制”选择组合：

- **工具与权限**：选择工具，设置继承、询问、允许或禁止，以及单个文件工具的范围。
- **执行与沙盒**：选择本机 / Docker / Windows 原生预览，设置文件范围、只读、联网、HTTP 主机和凭据名单；原生预览提供工作区选择、检测、管理员初始化和移除本机授权。
- **上下文策略**：选择继承、自动压缩或关闭，并配置 token 预留、近期保留和摘要要求。

保存后，新会话使用新版本。已有会话继续使用快照；在空闲时“应用新版组合”才更新。设置页的“Runtime → 管理执行与沙盒”也可进入组合配置。

## 授权如何生效

权限确认回答“这次动作是否获得允许”；执行后端负责实际运行位置。显式禁止、文件范围、只读、断网和凭据规则优先，`full_access` 不会覆盖它们。成员与父组合的工具、文件、网络、变量名单取交集；父组合使用沙盒时成员保持同一后端，Docker 镜像也不能被成员更换。

### 本机后端

旧组合默认保持本机执行。文件工具可以审核工作区范围或禁止写入，HTTP 工具可以限制联网及主机；但本机命令有当前用户的系统权限。若组合要求只读、仅工作区、禁止联网或 HTTP 主机名单，无法强制这些边界的本机命令会被拒绝。此时可禁用命令工具，或改用 Docker。

进程只继承必要的系统路径与临时目录变量，加上明确授权的变量，不再继承全部宿主环境。依赖其他环境变量的旧自定义工具需要将名称加入名单。模型 API 认证仍由 Tao 单独管理。

### Docker 工具沙盒

需要 Docker Desktop（Linux 容器后端）或本机 Linux Docker Engine，以及包含 Node 22 的镜像。首次准备：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-sandbox.ps1
```

脚本检查本机服务，使用固定摘要的 Node 22 / Bookworm slim 基础镜像构建 `tao-runtime:0.1.0`，增加 Python/pip/venv、Git、rg、curl、jq、zip/unzip 和 build-essential。先构建临时标签，完成离线、非 root、只读根目录工具验收后才更新正式标签。Docker 安装和虚拟化前提仍需用户自行完成；Windows 原生与本机执行不依赖此镜像。镜像保存在 Docker 已配置的存储位置，脚本不更改其数据目录。

新构建的安装版携带镜像配方，可在“执行与沙盒”选择 Docker 并点击“准备 Tao 基础镜像”，无需宿主 Git/Node 或源码。首次准备需要访问镜像与 Debian 软件源；不会开放任务的联网权限。旧组合显式配置的镜像不自动迁移。普通“检测沙盒环境”仍只检查服务和镜像存在，不下载、不调用模型。镜像未托管到公共仓库，不能直接远程拉取 Tao 本地标签。配方、项目依赖与维护说明见 [镜像说明](../../src-tauri/runtime/docker/README.md)。

选择 Docker 时，界面默认设置为工作区范围及断网。运行时：

1. 检查服务和镜像，只接受本机 Docker 地址与 Linux 容器；镜像按检测得到的 ID 运行，不自动拉取，不静默回退本机。
2. 每个操作建立临时容器，只将指定项目挂载到 `/workspace`；不挂载整个用户目录、磁盘或 Docker 接口。工作区可选只读或可写。
3. 根文件系统只读，临时文件使用限额 tmpfs；非 root 用户、去除 capabilities、禁止提权，并限制内存、CPU、进程数。每个操作最多 120 秒，容器内有独立的超时监督进程。
4. 内置命令和自定义程序/命令经同一执行接口；文件读写、编辑、目录和搜索操作在容器内访问工作区。容器内可用程序取决于镜像，Windows 程序路径不能直接用于 Linux 容器。
5. 停止或超时会回收该操作的容器。工作区已经发生的修改不回滚，多个成员也仍会共用项目文件。

这是工具容器隔离，不把模型 SDK、桌面程序、所有扩展和整台电脑放进虚拟机。任意 Extension 可运行本机代码，因此与受限执行策略同时启用时会拒绝创建会话。Windows 原生预览见下节；逐成员独立工作副本与 Docker 跨进程执行租约尚未接入，原生执行器有自己的租约与恢复日志。

容器文件工具单文件读取上限 1 MB；大文件可用命令分段读取。容器搜索使用 JavaScript 正则 / 字面匹配与 glob，跳过 `.git`、`node_modules` 和符号链接，不自动解析 `.gitignore`；单次最多搜索 10000 个文件。工具说明已明确这些差异，本机搜索仍保留原实现。

### Windows 原生工具沙盒（预览）

0.2.0 接入独立 AppContainer + Job Object 执行器，无需 Docker，旧组合仍默认本机运行。Windows 11 23H2 已完成核心接口与实际 SDK 流程验证；Windows 10 采用同一套兼容 API 和能力探测，真机验收后补。

开发启动 `npm.cmd run tauri dev` 会自动编译辅助组件；需要单独编译时执行（不生成 MSI）：

```powershell
npm.cmd run tao:node
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-windows-sandbox.ps1
```

在“定制 → 执行与沙盒”选择 **Windows 原生（预览）**，选择会话将使用的具体工作区，点击“管理员初始化”，按 Windows UAC 提示完成后检测。保存组合，再新建会话或空闲时应用新版组合。

命令行也可准备或移除：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-windows-sandbox.ps1 -Prepare -WorkspacePath 'D:\MyProject'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-windows-sandbox.ps1 -Remove
```

初始化只给 Tao 专用兼容能力授予 NT 路径查询、非继承的磁盘 / 祖先目录元数据读取、MountPointManager 读取及 NUL 读写；不授予列目录、文件内容或磁盘根目录写入，不给所有 AppContainer 放权，不创建本地账户、服务或防火墙规则。受管理员保护的 `HKLM\SOFTWARE\Tao\WindowsSandbox\CompatibilityV1` 记录目录授权，移除时精确撤销。部分设备权限每次重启重置，因此**重启后可能需要再次初始化**，当前未安装自动修复服务。

“移除本机原生授权”影响本机全部 Tao 原生组合，需管理员确认，请先停止活动原生工具。受保护的 ProgramData 锁文件由活动执行共享持有，准备/移除时要求独占；崩溃后由 Windows 释放。MSI 升级保留共享授权；明确卸载时调用 MSI 内嵌 helper 清理，活动执行会阻止卸载。会话、组合及项目文件保留。若曾授权的磁盘离线，需重新连接后重试移除。取消 UAC 可稍后重试，不会切换本机执行。

每条操作有独立身份与临时目录，工作区按配置只读或可写，命令最长 120 秒。文件工具在隔离内运行；命令工具名保留 `bash` 以兼容现有会话，但实际使用 **Windows PowerShell**，已有 Bash / cmd 命令需按此环境调整。模型与受控 HTTP 工具留在 Tao 宿主；原生命令始终断网。“允许联网”只影响受控 HTTP 工具。系统已向普通 AppContainer 开放的公共资源仍可能可读，不能当作完整虚拟机或只含工作区的磁盘。

运行时只继承必要环境和明确授权的凭据，HOME 与临时目录指向本次工具目录；使用 Tao 私有兼容 Node 22.23.3，Node/npm 在 Tao 数据目录下缓存并逐文件核对 SHA-256，不替换系统 Node。源码首次构建需要 Python 3、现有 C++ 工具链及下载官方源码，后续复用缓存；安装用户使用随包资源，无需自行编译。关闭控制通道、取消及前台退出回收 Job 后代，遗留授权日志可在下次执行前清理；活动执行受租约保护。

随包 Node 已修复同步/异步子进程管道，fork IPC、npm 本地测试、TypeScript 编译、npx 本地工具、esbuild 完整打包和带 TypeScript 配置的 Vite 生产构建已实际验证。命令建议使用提供的 `node`、`npm.cmd` 和 `npx.cmd`；显式指定其他 Node 不自动获得补丁。相对路径、普通绝对路径和 Windows 扩展路径均经过同一工作区检查。

命令临时使用 Z: 至 E: 中未占用的盘符，将所选工作区变成盘符根目录，构建工具无须向宿主祖先查找。输出提示映射关系；盘符在当前 Windows 登录会话可见，结束后释放，不覆盖已有映射，也不扩大文件权限。后续工具使用原工作区路径或相对路径，不能复用临时盘符。文件 worker / 普通结构化程序调用保持原路径。执行期间工作区根目录被固定，防止改名或替换；helper 崩溃时 Job 与非持久链接一起关闭，遗留 ACL 通过已有日志恢复。

**当前限制：** 固定宿主绝对路径或从工作区外加载配置/依赖的构建仍可能失败，应把项目依赖放入工作区；空闲盘符不足时命令明确拒绝。命令始终断网，不能因此宣称 npm 联网安装已支持。已有 reparse point（含 junction）、硬链接、超过 10000 条目的授权目录树、包含 Tao 程序 / 状态目录的工作区会被拒绝；硬链接需要换成独立副本。授权使用固定父目录下的对象句柄，不递归跟随链接；这不等于已抵御同权限宿主程序或管理员的一切竞争。跨 Windows 用户和真实桌面重启流程仍待验收。最新证据见 [0.2.0 验收](../验证/2026-10-21-0.2.0发布验收.md)及 [构建兼容与清理](../验证/2026-10-21-原生沙盒构建兼容与清理.md)；历史 Node 和接入失败保留在 [Node 与路径修复](../验证/2026-10-20-原生Node兼容与相对路径.md)、[原生后端记录](../验证/2026-10-20-Windows原生后端接入.md)。

## 联网与凭据

- “跟随后端默认值”：本机允许联网，Docker / Windows 原生禁止工具联网。
- “禁止联网”：拒绝 HTTP 工具，容器使用无网络模式；模型服务和压缩请求仍由 Tao 连接。
- “允许联网”：容器可使用普通 bridge 网络，不承诺按域名限制 shell。
- 设置 HTTP 主机名单后：与工具本身名单取交集，使用准确主机名，不支持通配符。容器命令保持断网，只有 Tao 代理的 HTTP 工具可以请求获准主机；重定向不跟随。
- 凭据名单只写变量名称，例如 `SERVICE_TOKEN`。HTTP 请求头的 `{{env:SERVICE_TOKEN}}` 引用也要获得授权。容器仅接收明确授权的变量，平台及代码注入相关保留变量不能被覆盖。

HTTP 工具在 Tao 宿主代理中执行，网络规则在代理入口检查；容器网络隔离不代替该检查。当前没有面向任意进程的域名级网络代理。

## 压缩策略

| 模式 / 参数 | 行为 |
|---|---|
| 沿用 Runtime 默认策略 | 保留当前 Runtime 设置，不写回全局 settings.json；实际会话记录显示运行时绑定的配置 |
| 自定义自动压缩 | 使用组合快照中的预留和保留量；接近模型窗口上限或溢出时由内核触发 |
| 关闭自动压缩 | 不自动整理历史；超出模型限制可能报错，不自动删消息 |
| 预留 token 数 | 默认 16384，可配置 256–131072；近似触发线为模型窗口减去预留量 |
| 保留近期 token 数 | 默认 20000，可配置 512–131072；按消息边界选取，实际保留量不保证完全等于参数 |
| 摘要补充要求 | 自动模式下追加到真正的摘要模型调用；不重复放入每轮主系统指令，不授予工具能力 |

自动模式要求预留量与近期保留量之和小于模型上下文窗口。摘要使用当前模型及认证，产生独立用量；主会话和每个成员分别应用自己的策略。设置失败不会静默退回另一个策略。

压缩仍使用同一内核的准备、摘要和会话归档机制，不建立另一套会话树。摘要写入 SDK JSONL，会话工作过程显示实际开始、完成、停止或失败。初始上下文页保留首次记录，不会随压缩覆盖；独立摘要浏览、逐轮完整追踪、压缩次数限制和团队总 token / 费用硬预算尚未开放。

## 开发验证

```powershell
npm.cmd run check
npm.cmd run test:agents
npm.cmd run test:sandbox
```

`test:sandbox` 需要已准备好的镜像，使用临时工作区和本地模拟模型，覆盖实际容器读写、只读、断网、目录链接、环境隔离、取消清理、缺镜像不回退，以及 SDK 全工具链与真实压缩调用。不使用用户 API Key 或真实模型。

参考实现边界：[Docker 运行参数](https://docs.docker.com/reference/cli/docker/container/run/)、[Docker Engine 安全说明](https://docs.docker.com/engine/security/)。这些参数限制容器权限和资源，不代表对所有宿主漏洞的安全保证。

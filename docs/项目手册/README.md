# Tao 项目手册

最后更新：2026-10-20

这是一份面向 Tao 后续开发、发布和维护的统一项目手册。它把当前项目中分散在代码、设计文档和开发记录里的信息整理成一条可追溯的入口。

## Tao 是什么

```text
Tao = Tauri 桌面产品 + Tao Runtime 装配层 + Tao 智能体内核
```

产品和内核统一称 Tao。内核基于 Pi 固定源码快照，源码位置和原始许可证保留，用户无需另外维护它。

当前产品目标：

- 在 Windows 桌面上提供中文 Agent 工作台；
- 使用一个常驻 Node Runtime 托管多个独立 Pi AgentSession；
- 支持多会话、独立工作区、模型配置、流式回答、工具状态、权限确认和定制 Agent；
- 通过 MSI 生成可以在没有 Tao 源码和 Node.js 的 Windows x64 电脑上安装的软件。

## 最常用命令

以下命令都在 Tao 项目根目录执行：

```powershell
cd <Tao 项目根目录>

# 类型检查和 Rust 检查
npm.cmd run check

# 组合、权限和工具执行回归（本地模拟模型）
npm.cmd run test:agents

# 启动 Tauri 开发模式
npm.cmd run tauri dev

# 只启动 Vite 前端
npm.cmd run dev

# 生成发布准备资源，不生成安装包
npm.cmd run tao:prepare

# 生成 Windows x64 MSI
npm.cmd run tao:release

# 设置版本并生成 MSI（2.1 会规范化为 2.1.0）
npm.cmd run tao:release -- 2.1
```

当前发布命令默认只生成 MSI。NSIS 仍可单独尝试，但不作为当前默认发布格式：

```powershell
npm.cmd run tao:release:nsis
```

## 当前状态标签

手册使用以下含义：

- **已实现**：代码和 UI 已经形成可使用的产品功能。
- **已接入但有限制**：主链路已经存在，但仍有明确范围或验证缺口。
- **页面预留**：有数据字段、入口或基础接口，但还不是完整产品功能。
- **未实现**：设计中提到，但当前代码没有完整实现。

## 重要结论先看

1. 开发时不需要先进入 `src-tauri`，从 Tao 根目录执行 `npm.cmd run tauri dev`。
2. `cargo clean --manifest-path src-tauri/Cargo.toml` 只清理 Rust 构建产物，不删除源码、Pi 副本或 `%USERPROFILE%\.tao`。
3. 发布版 MSI 已内置 Node、Tao Runtime、Pi 源码和 Pi 依赖，目标电脑不需要安装 Node.js、Rust 或 Tao 源码。
4. 发布版仍依赖 Windows WebView2，并且使用模型时需要能够访问对应的 API 或网关。
5. 当前只保证 Windows x64；没有正式的 macOS、Linux 或便携 ZIP 发布流程。
6. `src-tauri/resources`、`src-tauri/target`、`dist`、`node_modules` 和 `.tao-release-cache` 都是可再生或发布过程目录，不应被当作核心源码。
7. `%USERPROFILE%\.tao` 是用户数据目录，不属于项目源码。是否迁移它，取决于是否要保留配置和会话。
8. `vendor/pi` 是 Tao 内核的固定源码副本，可以按产品需要修改；保留源码来源、版本、变更和验证记录。
9. 发布版本参数会同步写入项目版本文件；同一版本重复构建会覆盖输出目录中的同名 MSI。

## 文档维护规则

每次功能讨论结束并开始编码前：

1. 先更新 `docs/开发TODO.md`；
2. 如果影响发布、数据目录、事件协议或架构边界，同时更新本手册；
3. 完成功能后运行对应的检查和验证；
4. 如果发现“设计文档写了但代码没有”或“代码已经改变但文档没更新”，在代码审查文档中记录并修正。

本手册不替代 Pi 的源码和官方文档，也不把 Pi 的内部实现细节复制成第二套规范。它只记录 Tao 当前实际采用的集成方式和产品边界。

# Tao 从零开始配置开发环境

> 适用对象：第一次拉取 Tao 仓库后，想在 Windows 电脑上运行 `npm.cmd run tauri dev` 的开发者或新手用户。

本文不假定你已经安装好 Node、Rust 或 Visual Studio。文中的项目路径统一不写死，使用 `<你的项目根目录>` 代替克隆下来的 Tao 目录位置。

## 推荐：一键准备

克隆仓库后，在项目根目录的 PowerShell 中执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-dev.ps1
npm.cmd run tauri dev
```

准备脚本会检查 Windows x64、Node、Rust MSVC、C++ 编译器、Windows SDK、WebView2 和 Git；按需安装缺失的必需组件，使用两份锁文件安装 Tao 与 Pi 依赖，并运行 TypeScript、Rust 和 Pi 工作区验证。重复运行可用于恢复未完成的安装。安装 C++ Build Tools 时可能出现管理员授权窗口；如提示重启，重启后执行同一命令。

Pi 源码快照不提交 `packages/ai/src/providers/data/*.json`。脚本会从与快照版本相同的 `@earendil-works/pi-ai` npm 发布包提取固定模型数据，再运行 Pi 自带的 `check:model-data` 验证；直接执行两次 `npm install` 不足以启动完整 Agent。

默认优先使用 `D:\TaoDev` 保存便携 Node（仅在现有 Node 不合格时安装）、Rust 工具链、下载包和 npm 缓存。仓库位于 D 盘时，两个 `node_modules` 和 Rust 构建产物也位于 D 盘。已有合格的 Node、C++ 工具和 WebView2 会直接复用，脚本不会搬迁它们。Microsoft 的共享组件和 WebView2 仍可能由官方安装器写入系统盘。没有 D 盘时默认使用 `%LOCALAPPDATA%\TaoDev`；可显式指定目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-dev.ps1 -ToolsRoot 'E:\TaoDev'
```

只查看缺失项、不安装时使用 `-CheckOnly`。脚本成功后会生成被 Git 忽略的 `.tao-dev-config.json`，供 `npm.cmd run tauri dev` 和 `scripts\tao.ps1` 恢复工具路径。普通 PowerShell 中不一定能直接运行 `cargo`，但 Tauri 开发命令会自动找到 D 盘 Rust，无需再安装一次。开发、检查和构建也可通过 `tao.ps1` 运行：

如果官方 Rust 下载源在国内网络长期无响应，可改用 `-UseChinaMirror`：Rust 组件下载使用 RsProxy，且只在新建的 D 盘 Cargo 配置中设置 crates.io 镜像，不覆盖已有配置。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-dev.ps1 -UseChinaMirror
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\tao.ps1 dev
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\tao.ps1 check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\tao.ps1 release
```

准备脚本解决开发机环境问题，不代表 MSI 安装后的功能已经验收。安装版用户不需要运行此脚本。

## 1. 先明确目标

本项目的开发启动链路是：

```text
npm.cmd run tauri dev
  -> Tauri 先启动 Vite
     -> 再编译并启动 Rust 桌面应用
        -> 应用启动 Node Runtime
           -> 加载 vendor/pi
```

因此要成功启动，开发机至少需要：

- Windows x64
- Node.js 22.19.0 或更高版本和 npm；脚本在缺失时安装 Node 22.19.0
- Rust stable，默认工具链必须是 `x86_64-pc-windows-msvc`
- Visual Studio C++ Build Tools（2022 或兼容的较新版本）的“使用 C++ 的桌面开发”工作负载
- Windows WebView2 Runtime
- PowerShell
- Git，推荐安装；`Files` 面板的 Git Diff 功能还需要工作区可调用 `git`

下面的步骤就是把这些条件逐个补上。

## 2. 安装 Git

如果已经能用 `git --version` 输出正常版本，跳过本节。否则先安装 [Git for Windows](https://git-scm.com/download/win)。

克隆项目时，把 `<仓库地址>` 替换成实际的 GitHub 地址，把 `<你的项目根目录>` 替换成你希望存放项目的目录：

```powershell
git clone <仓库地址>
Set-Location <你的项目根目录>
```

后续所有 `npm.cmd`、`cargo` 命令都从项目根目录执行，不需要先进入 `src-tauri`、`src` 或 `vendor/pi`。

## 3. 安装 Node.js 22 LTS

### 3.1 检查是否已安装

```powershell
node --version
npm.cmd --version
```

建议 `node` 输出的是 22.x 版本。

如果没安装，可以通过官方下载页安装 [Node.js 22 LTS](https://nodejs.org/en/download)，或者在支持 winget 的机器上执行：

```powershell
winget install OpenJS.NodeJS.LTS
```

安装后关闭并重新打开 PowerShell 再验证。

Windows PowerShell 下优先使用 `npm.cmd`。直接输入 `npm` 可能走 `npm.ps1`，个别环境会受 PowerShell 执行策略影响，而 `npm.cmd` 更稳定。

## 4. 安装 Rust stable

### 4.1 安装

在 PowerShell 中运行：

```powershell
Invoke-WebRequest -Uri "https://win.rustup.rs/x86_64" -OutFile "$env:TEMP\rustup-init.exe"

& "$env:TEMP\rustup-init.exe" -y --default-toolchain stable-x86_64-pc-windows-msvc
```

上面的命令会：

- 下载 `rustup-init.exe`
- 静默安装 Rust
- 把默认工具链设置为 `stable-x86_64-pc-windows-msvc`

如果下载失败，也可以从浏览器打开 <https://win.rustup.rs/x86_64> 手动下载并运行，交互安装时选择默认选项即可。安装完成后重新打开 PowerShell。

### 4.2 验证

```powershell
rustup --version
rustc --version
cargo --version
rustup show
```

`rustup show` 的关键输出应当是：

```text
Default host: x86_64-pc-windows-msvc
stable-x86_64-pc-windows-msvc
x86_64-pc-windows-msvc
```

如果 `rustup`、`rustc`、`cargo` 仍提示“无法识别”，先重新打开 PowerShell；仍无效说明 Rust 未安装成功。

## 5. 安装 Visual Studio 2022 Build Tools

Tao 的 Rust 依赖 MSVC 链接器和 Windows SDK。只安装 Rust 是不够的，还必须具备 C++ 构建工具。

### 5.1 命令行安装

右键 PowerShell，选择“以管理员身份运行”，然后执行：

```powershell
Invoke-WebRequest -Uri "https://aka.ms/vs/17/release/vs_BuildTools.exe" -OutFile "$env:TEMP\vs_BuildTools.exe"

& "$env:TEMP\vs_BuildTools.exe" --wait --quiet --norestart --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.Windows11SDK.26100 --includeRecommended
```

安装会持续一段时间，等待它完成。如果需要重启电脑，按提示重启后再继续。

### 5.2 图形界面安装

如果命令行安装不方便，可以打开 [Visual Studio Build Tools 下载页](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，下载并运行 `vs_BuildTools.exe`，然后在“工作负载”里勾选：

- **使用 C++ 的桌面开发**

默认推荐项至少应包含：

- MSVC v143 - VS 2022 C++ x64/x86 生成工具
- Windows 11 SDK，例如 10.0.26100.x
- 如果只安装了 MSVC 而没安装 Windows SDK，链接阶段会缺少 `dbghelp.lib`、`kernel32.lib` 等 SDK 库

安装完成后同样需要重新打开 PowerShell。

### 5.3 验证

```powershell
& 'C:\Program Files (x86)\Microsoft Visual Studio\Installer\vswhere.exe' -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
```

输出一个 Visual Studio Build Tools 安装路径即表示存在。没有输出说明尚未安装成功。

## 6. 安装 WebView2 Runtime

Tauri 依赖 WebView2。现代 Windows 10/11 上通常会预装。

先检查：

```powershell
Test-Path 'C:\Program Files (x86)\Microsoft\EdgeWebView\Application'
```

输出 `True` 表示已经存在；输出 `False` 时，从 [WebView2 Runtime 下载页](https://developer.microsoft.com/microsoft-edge/webview2/) 安装 Evergreen Bootstrapper。

## 7. 安装项目依赖

从项目根目录开始。

### 7.1 安装 Tao 依赖

```powershell
Set-Location <你的项目根目录>
npm.cmd install
```

### 7.2 安装内置 Pi 依赖

```powershell
Set-Location <你的项目根目录>\vendor\pi
npm.cmd install --ignore-scripts
Set-Location ..\..
```

安装完成后验证 Pi 依赖的关键文件存在：

```powershell
Test-Path '.\vendor\pi\node_modules\tsx\dist\preflight.cjs'
Test-Path '.\vendor\pi\node_modules\tsx\dist\loader.mjs'
Test-Path '.\vendor\pi\node_modules\.bin\tsx.cmd'
```

三个都应输出 `True`。如果 `preflight.cjs` 或 `loader.mjs` 不存在，说明 `vendor/pi` 依赖没装好，重新执行本节的 Pi 安装命令。

### 7.3 补齐 Pi 模型数据

使用一键脚本时这一步自动完成。如果选择手动安装，在项目根目录执行：

```powershell
$piAi = Get-Content .\vendor\pi\packages\ai\package.json -Raw | ConvertFrom-Json
$archive = npm.cmd pack "$($piAi.name)@$($piAi.version)" --silent | Select-Object -Last 1
$dataDir = '.\vendor\pi\packages\ai\src\providers\data'
New-Item -ItemType Directory -Force $dataDir | Out-Null
tar.exe -xf $archive -C $dataDir --strip-components=4 package/dist/providers/data
npm.cmd --prefix .\vendor\pi\packages\ai run check:model-data
Remove-Item -LiteralPath $archive
New-Item -ItemType Directory -Force .\src-tauri\resources | Out-Null
```

这会下载与仓库 Pi AI 包版本相同的模型数据快照；不要使用实时模型目录重新生成来代替固定快照。`src-tauri/resources` 空目录也必须存在，Tauri 在 Debug 模式仍会检查该路径。

## 8. 验证环境是否具备

从项目根目录执行：

```powershell
node.exe --check .\src-tauri\runtime\tao-runtime.mjs
npm.cmd run check
```

`npm.cmd run check` 会同时执行：

```text
tsc --noEmit
cargo check --manifest-path src-tauri/Cargo.toml
```

如果 `tsc` 和 `cargo check` 都没有报错，就说明 Node、Rust、MSVC 和项目依赖已经基本具备。

## 9. 启动开发模式

成功通过检查后，从项目根目录运行：

```powershell
npm.cmd run tauri dev
```

Tauri 会根据 `src-tauri/tauri.conf.json` 先启动 Vite，再编译并启动 Rust 桌面应用，默认 Vite 地址是：

```text
http://localhost:1420
```

第一次 Rust 编译会比较慢，磁盘也会生成较大的 debug 构建缓存，这是正常现象。

只关心前端页面时也可以运行：

```powershell
npm.cmd run dev
```

但这种方式不能验证 Rust command、Node Runtime、Pi 会话和文件系统能力。要验证完整桌面应用，必须使用 `npm.cmd run tauri dev`。

## 10. 常见问题

### `rustup`、`rustc` 或 `cargo` 无法识别

先确认已经安装 Rust。安装完成后必须重新打开 PowerShell，再执行：

```powershell
rustup show
```

### `cargo check` 或 `tauri dev` 报找不到 `link.exe`

这类错误通常表示 MSVC 构建工具或 Windows SDK 不完整。除了“使用 C++ 的桌面开发”工作负载，还要确认已经安装 Windows 11 SDK。

如果链接阶段报：

```text
LINK : fatal error LNK1181: 无法打开输入文件“dbghelp.lib”
```

说明 SDK 库不完整。使用管理员 PowerShell 对已有 Build Tools 执行：

```powershell
& 'C:\Program Files (x86)\Microsoft Visual Studio\Installer\setup.exe' modify --installPath 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools' --add Microsoft.VisualStudio.Component.Windows11SDK.26100 --includeRecommended --quiet --norestart
```

安装完成后重新打开 PowerShell，再验证：

```powershell
Test-Path 'C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\um\x64\dbghelp.lib'
```

输出 `True` 后再重试 `npm.cmd run check`。

### `node` 无法识别

确认 Node.js 已安装；如果刚安装，重新打开 PowerShell。优先使用 Node.js 22 LTS。

### `npm.ps1` 提示“禁止运行脚本”

这种错误通常发生在直接运行 `npm` 而不是 `npm.cmd` 时。可以：

```powershell
npm.cmd --version
npm.cmd run check
```

如果仍要使用 `npm` 命令，请按你的安全策略调整 PowerShell 执行策略，不要在不了解风险的情况下全局放开。

### 端口 1420 已被占用

出现 `Port 1420 is already in use` 时，通常只是旧的 Vite/Tao 进程还在运行。关闭旧开发进程、旧 Tao 窗口和旧终端后重试：

```powershell
npm.cmd run tauri dev
```

### `tao.exe` 无法删除或访问被拒绝

通常是因为旧的 Tao 进程仍在运行。先关闭 Tao 窗口和开发终端，再重试，不要反复清理 `target`。

### `vendor/pi/node_modules/tsx/dist/preflight.cjs` 不存在

说明 Pi 依赖没有准备好。重新执行：

```powershell
Set-Location <你的项目根目录>\vendor\pi
npm.cmd install --ignore-scripts
Set-Location ..\..
```

### 首次编译特别慢

Rust 首次编译和依赖下载会消耗较长时间；之后通常复用增量缓存，启动会快很多。

### 模型不可用

开发环境启动成功和模型能正常工作不是一回事。模型调用还需要 Provider、模型配置、API Key 以及可访问的 API 或网关，这些不属于本文档的编译环境范围。

## 11. 不要混淆的边界

- 只修改 Tao 自己的代码，不要把直接修改 `vendor/pi` 当作普通功能实现方式。
- 用户配置、API Key 和会话数据位于 `%USERPROFILE%\.tao`，不属于项目源码。
- `node_modules`、`vendor/pi/node_modules`、`dist`、`src-tauri/target` 都是可再生的依赖或构建目录。
- 开发机环境安装完成后无需再进入 `src-tauri` 或 `vendor/pi` 执行启动；只需要从项目根目录运行 `npm.cmd run tauri dev`。

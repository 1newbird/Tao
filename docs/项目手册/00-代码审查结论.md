## 已确认的架构事实

### 1. Tauri、Rust、Node Runtime、Pi 的链路已经存在

当前运行链路是：

```text
React
  -> Tauri invoke / event
  -> Rust command 和 TaoRuntimeManager
  -> 一个常驻 tao-runtime.mjs
  -> 多个独立 Pi AgentSessionRuntime
  -> Provider、模型和工具
```

开发模式由系统 `node.exe` 加载 `src-tauri/runtime/tao-runtime.mjs` 和 `vendor/pi`。

发布模式由安装目录内置的 `node/node.exe` 加载
`runtime/tao-runtime.mjs` 和 `pi`。这些内容在构建时由 `src-tauri/resources` 生成；发布模式不会回退到编译机源码目录。

### 2. 会话隔离已经按 `conversationId` 建立

每个会话拥有：

- 独立的 Pi Session 文件；
- 独立的工作区路径；
- 独立的 Provider、Model 和思考模式；
- 独立的权限模式；
- 独立的生成状态、活动摘要和 Trace；
- 独立的 `requestId` 路由。

多个会话共用一个 Runtime PID 是设计结果，不代表所有会话只能串行运行。

### 3. Pi 负责 Agent loop

当前 Tao 没有在 React 或 Rust 中重新实现：

- 模型调用循环；
- 工具选择；
- 工具执行结果回传；
- 上下文压缩；
- Pi 自动重试；
- Pi Session 内部上下文管理。

Tao Runtime 负责装配配置、托管会话、转发事件和提供产品级状态。

### 4. 主请求生命周期（2026-10-19 源码更新）

Pi 运行期间，Node Runtime 会持续发出 Tao Runtime 事件，React 可以实时显示：

- 思考增量；
- 正文增量；
- 工具状态；
- `preamble` 工作说明；
- Trace；
- 权限请求；
- 重试、压缩、队列和完成状态。

早期 Rust `send_message` 通过外层 RPC 等待最终结果，保护时间为 30 分钟。本批源码已改为：

- 界面事件可以实时更新；
- 保存用户消息和任务身份后返回启动回执，后台等待 Node 的最终响应；
- 原子归档结果后发布终态，并提供运行状态补查；
- 保存失败只重试保存；重启将遗留任务标为中断，不自动执行外部操作。

这项改动已覆盖源码回归，原生桌面与新 MSI 安装仍需单独验收。短控制 RPC 与 Node 的最终响应协议仍然保留，不能据此声称所有命令均无等待或支持自动断点续跑。

## 当前实现与设计文档的差异

### 已经实现但仍有范围限制

- Files 面板支持当前工作区目录、Markdown/MDX 预览和 Git 文本 Diff；非 Git 工作区的历史改动追踪还没有实现。
- Skills 已统一使用 `%USERPROFILE%\.tao\skills`，但完整的 Skill 管理器和编辑器尚未完成。
- 自定义工具支持命令和 HTTP 两种第一版形式、JSON Schema、启用开关、测试和权限模式；任意 Extension Hook 编辑器尚未完成。
- Provider 支持内置目录、保存的 Provider 档案、`GET /models` 拉取和模型切换；更复杂的 Provider 运行时改写仍未做。
- 权限审计支持工具调用前询问、允许或拒绝；另有可选的本机 Docker 工具执行后端，提供工作区挂载、只读、断网、环境名单及资源限制。审计与执行隔离各自生效，任意扩展不在容器隔离范围内，受限组合禁止加载扩展。
- 主题、强调色、复制、导出和附件已经存在，但仍属于 Tao 产品壳层能力，不改变 Pi 内核。

### 尚未完成或需要后续验证

- 在没有 Node.js、没有 Tao 源码的干净 Windows x64 电脑上完成 MSI 安装和完整对话验证；
- 新主请求生命周期的原生桌面与安装验收；
- NSIS 资源压缩耗时和资源裁剪；
- 代码签名；
- macOS、Linux 和其他架构发布；
- 完整的 Extension 编辑器、Agent 组合套装和配置版本管理；
- Docker 后端的原生桌面及新安装包验收，Windows 原生隔离、逐成员独立工作副本与域名代理；
- 非 Git 项目的文件变更历史和更完整的 Diff；
- 中断后的继续执行与未落盘结果恢复（当前仅提供中断提示，不自动重放）。

## 维护判断

当前项目已经从“开发态原型”进入“可构建 Windows x64 安装包的第一版产品”，但仍不是最终发布闭环。最重要的剩余风险不是前端 UI，而是：

1. 干净电脑安装验证；
2. 任务状态恢复与外部副作用的核对；
3. 发布资源体积和安装体验；
4. 权限审计与沙盒边界的清晰区分；
5. 后续定制能力继续扩展时不能破坏已有发布资源路径。

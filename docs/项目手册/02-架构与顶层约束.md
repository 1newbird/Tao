# Tao 架构与顶层约束

## 1. 产品定位

Tao 是产品，Pi 是 Agent 引擎：

```text
Tao
 ├─ React + TypeScript 产品界面
 ├─ Tauri + Rust 桥接层
 ├─ 一个常驻 Tao Node Runtime
 │   ├─ Pi AgentSession A
 │   ├─ Pi AgentSession B
 │   └─ Pi AgentSession C
 └─ 用户目录 %USERPROFILE%\.tao
```

Pi 的源码在开发项目中位于 `vendor/pi`，发布时被整理到安装包 resources 中。用户不需要知道或维护一个独立的 Pi 产品目录。

## 2. 三层职责

### React UI

负责：

- 会话列表、设置、定制、主题和布局；
- 用户消息、思考、正文和工作过程展示；
- Runtime 状态、权限确认和错误提示；
- 工作区目录、Markdown 预览和 Diff 阅读；
- 发送、停止、steer、follow-up、重试和导出入口。

不负责：

- 根据用户问题判断是否需要工具；
- 实现 Agent loop；
- 实现模型重试或上下文压缩；
- 解析 Pi 原始工具结果；
- 持久化或跨事件传播 API key；设置表单填写期间可以在前端内存中暂存。

### Tauri + Rust

负责：

- Tauri command 和文件系统边界；
- 常驻 Node Runtime 的启动、停止、重启和状态；
- Runtime 请求 ID 的等待和分发；
- `conversationId`、`requestId` 路由；
- Tao 数据保存和迁移；
- 工作区目录安全检查；
- 将用户设置转换为 Pi 配置。

Rust 不应该变成第二个 Agent loop，也不应该把工具 stdout 或完整结果传给 React。

### Tao Node Runtime

负责：

- 加载 Pi SDK；
- 初始化共享 `ModelRuntime`；
- 创建和管理多个 Pi AgentSession；
- 为每个会话设置 cwd、模型、思考模式和定制配置；
- 转发 Pi 事件为 `tao-runtime-event`；
- 维护权限等待、Trace 和工作过程摘要；
- 将自定义工具注册到 Pi；
- 按会话执行 abort、steer、follow-up 和 close。

### Pi

负责：

- Agent loop；
- 模型调用；
- 工具选择和执行；
- Session 上下文；
- 上下文压缩；
- Provider 适配；
- 自动重试；
- Skill、Extension 和资源加载机制。

## 3. 当前进程和资源路径

### 开发模式

```text
系统 node.exe
  -> Tao/src-tauri/runtime/tao-runtime.mjs
  -> Tao/vendor/pi
  -> %USERPROFILE%\.tao
```

开发模式使用本机 Node 和仓库内 Pi 源码，便于调试。

### 发布模式

```text
Tao.exe
  -> 安装包 resources/node/node.exe
  -> 安装包 resources/runtime/tao-runtime.mjs
  -> 安装包 resources/pi
  -> %USERPROFILE%\.tao
```

发布模式不能依赖：

- 编译机的 Node.js；
- 编译机的 Tao 源码路径；
- 目标电脑上的 `vendor/pi`；
- 目标电脑上的 npm 或 Rust。

`src-tauri/src/runtime.rs` 对 Debug 和 Release 使用了不同资源解析路径。后续修改 Runtime 路径时，必须同时验证这两种模式。

## 4. 单 Runtime、多会话模型

Tao 生命周期内只启动一个 Node Runtime。Runtime 内部使用 Map 按 `conversationId` 保存会话句柄。

每个会话独立保存：

- `AgentSessionRuntime`；
- Pi session JSONL；
- `workspacePath`；
- Provider、Model、思考模式；
- 权限模式；
- 活动请求和 Trace。

并发约束：

1. 每个普通 prompt 必须有唯一 `requestId`；
2. 事件必须携带 `conversationId` 和 `requestId`；
3. 同一会话有活动 prompt 时，不能再启动第二个独立 prompt；
4. 生成中追加内容必须走 Pi 原生 `steer` 或 `followUp`；
5. 不同会话可以并发，切换当前 UI 会话不能暂停其他会话；
6. 权限弹窗必须携带所属会话，后台会话的权限请求不能被当前会话误处理。

## 5. Tao Runtime 事件边界

React 只订阅 Tao 的 `tao-runtime-event`，不直接绑定 Pi 的 JSONL 协议。

当前事件至少覆盖：

- `runtime`：启动、状态、保存、连接；
- `session`：会话准备和恢复；
- `turn`：开始、完成、中止；
- `message`：思考和正文增量；
- `tool`：工具开始、更新、结束；
- `context`：上下文整理和压缩；
- `retry`：自动重试；
- `queue`：steer/follow-up 队列；
- `permission`：询问、允许、拒绝；
- `trace`：工作过程节点；
- `metric`：ready、首次输出、完成耗时；
- `error`：产品级错误。

跨 Node、Rust、React 允许传递的内容必须是产品级摘要：

- 工具名称；
- 动作类型；
- 脱敏后的相对目标路径；
- 截断后的命令预览；
- 状态和耗时；
- 用户需要做出的权限决定。

禁止跨边界传递：

- API key；
- 完整系统提示词；
- 原始工具参数；
- 文件正文；
- stdout/stderr；
- 完整工具结果；
- 原始 Pi 事件 JSON；
- Provider 网关完整响应。

## 6. 提示词、工具和 Skills 的装配

当前 Tao 定制配置保存于：

```text
%USERPROFILE%\.tao\runtime\profile.json
```

当前支持：

- 系统提示词追加；
- 系统提示词替换；
- 会话附加提示词；
- 内置工具组合；
- Tao 自定义命令工具和 HTTP 工具；
- Tao Skills 开关。

Skills 统一放在：

```text
%USERPROFILE%\.tao\skills
```

不要要求用户再维护一个 Pi 产品目录。Runtime 使用 Pi 的资源加载能力，把 Tao 目录作为额外 Skill 路径。

## 7. 权限和沙盒的边界

Tao 当前有权限审计：

```text
Pi tool call / user bash
  -> Tao 规则判断
  -> 自动允许 / 询问 / 拒绝
  -> 继续执行或返回阻止结果
```

这不是沙盒。权限审计解决“是否允许动作”，沙盒解决“动作即使允许，也只能在什么隔离环境中执行”。当前 Tao 暂未提供 Docker、VM、Gondolin 或 Windows 原生沙盒后端。

## 8. 会话事实源

Pi session JSONL 是 Agent 上下文和消息事实源。Tao 当前还保存 `conversation.json`，用于快速加载 UI 和产品元数据，这是第一阶段过渡投影。

后续修改会话存储时，不能在 Tao 中再造一套与 Pi 不一致的会话树或压缩逻辑。

## 9. 顶层禁止事项

后续开发默认禁止：

- 修改 `vendor/pi` 作为普通功能实现手段；
- 在 Tao 重写 Agent loop；
- 根据问题内容动态猜测或开关工具；
- 在 Tao 实现第二套重试；
- 在 Tao 实现第二套上下文压缩；
- 把 `.tao` 当成 Agent 工作区；
- 把工作区路径保护误称为沙盒；
- 让发布版回退到开发机路径；
- 把发布生成资源提交进源码；
- 让一个会话启动两个独立 prompt；
- 依赖当前激活会话推断后台事件归属。

如果确实需要修改 Pi 内核，必须先形成单独的补丁策略、版本记录、发布验证和回滚方案，不能直接把 `vendor/pi` 改成无法追踪的工作副本。

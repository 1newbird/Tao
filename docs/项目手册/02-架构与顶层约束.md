# Tao 架构与顶层约束

## 1. 产品定位

产品和内核统一称 Tao。内核基于固定源码快照，开发代码保留在 `vendor/pi`，原始来源和许可证保留：

```text
Tao
 ├─ React + TypeScript 产品界面
 ├─ Tauri + Rust 桥接层
 ├─ 一个常驻 Tao Node Runtime
 │   ├─ Tao AgentSession A + 组合快照
 │   ├─ Tao AgentSession B + 组合快照
 │   └─ Tao AgentSession C + 组合快照
 └─ 用户目录 %USERPROFILE%\.tao
```

Pi 的源码在开发项目中位于 `vendor/pi`，发布时被整理到安装包 resources 中。用户不需要知道或维护一个独立的 Pi 产品目录。

## 2. 三层职责

### React UI

负责：

- 会话列表、设置、定制、主题和布局；
- 用户消息、思考、正文和工作过程展示；
- Runtime 状态、权限确认和错误提示；
- 工作区目录、Markdown 预览和 Diff 阅读；
- 发送、停止、steer、follow-up、重试和导出入口。

不负责：

- 根据用户问题判断是否需要工具；
- 实现 Agent loop；
- 实现模型重试或上下文压缩；
- 解析 Pi 原始工具结果；
- 持久化或跨事件传播 API key；设置表单填写期间可以在前端内存中暂存。

### Tauri + Rust

负责：

- Tauri command 和文件系统边界；
- 常驻 Node Runtime 的启动、停止、重启和状态；
- Runtime 请求 ID 的等待和分发；
- `conversationId`、`requestId` 路由；
- Tao 数据保存和迁移；
- 工作区目录安全检查；
- 将用户设置转换为 Pi 配置。

2026-10-19 起，主请求由 `PromptRunManager` 管理持久任务身份：先将用户消息与 `starting` 记录原子保存，再派发 Node `prompt`。Tauri 的发送命令返回短回执，不等待模型整轮完成；Runtime 响应由后台回调归档，完成状态通过 `tao-prompt-run` 发布，并可经 `list_prompt_runs` / `get_prompt_run` 补查。Node 的 prompt 协议仍在结束时返回最终消息，短控制 RPC 仍有超时保护。

同会话串行、不同会话并行；提交按请求编号和内容指纹去重。归档在会话变更锁内重新读取最新元数据，与结果一起原子写入。只有保存成功才发布终态；失败保留已计算结果并进入 `save_failed`，重试只重做磁盘提交。退出阻止新派发并回收后台；下次启动将遗留运行标为中断，不自动重放工具操作。

Rust 不应该变成第二个 Agent loop，也不应该把工具 stdout 或完整结果传给 React。

### Tao Node Runtime

负责：

- 加载 Pi SDK；
- 初始化共享 `ModelRuntime`；
- 创建和管理多个 Pi AgentSession；
- 为每个会话设置 cwd、模型、思考模式和定制配置；
- 转发 Pi 事件为 `tao-runtime-event`；
- 维护权限等待、Trace 和工作过程摘要；
- 将自定义工具注册到 Pi；
- 按会话执行 abort、steer、follow-up 和 close。

### Pi

以下原生 API 与路径保留历史名称，产品统称 Tao 内核，允许根据需求修改。

负责：

- Agent loop；
- 模型调用；
- 工具选择和执行；
- Session 上下文；
- 上下文压缩；
- Provider 适配；
- 自动重试；
- Skill、Extension 和资源加载机制。

## 3. 当前进程和资源路径

### 开发模式

```text
系统 node.exe
  -> Tao/src-tauri/runtime/tao-runtime.mjs
  -> Tao/vendor/pi
  -> %USERPROFILE%\.tao
```

开发模式使用本机 Node 和仓库内 Pi 源码，便于调试。

### 发布模式

```text
Tao.exe
  -> 安装目录 node/node.exe
  -> 安装目录 runtime/tao-runtime.mjs
  -> 安装目录 pi
  -> %USERPROFILE%\.tao
```

发布模式不能依赖：

- 编译机的 Node.js；
- 编译机的 Tao 源码路径；
- 目标电脑上的 `vendor/pi`；
- 目标电脑上的 npm 或 Rust。

`src-tauri/src/runtime.rs` 对 Debug 和 Release 使用了不同资源解析路径。后续修改 Runtime 路径时，必须同时验证这两种模式。

## 4. 单 Runtime、多会话模型

Tao 生命周期内只启动一个 Node Runtime。Runtime 内部使用 Map 按 `conversationId` 保存会话句柄。

每个会话独立保存：

- `AgentSessionRuntime`；
- Pi session JSONL；
- `workspacePath`；
- Provider、Model、思考模式；
- 权限模式；
- 智能体组合 ID、版本和实际配置快照；
- 活动请求和 Trace。

并发约束：

1. 每个普通 prompt 必须有唯一 `requestId`；
2. 事件必须携带 `conversationId` 和 `requestId`；
3. 同一会话有活动 prompt 时，不能再启动第二个独立 prompt；
4. 生成中追加内容必须走 Pi 原生 `steer` 或 `followUp`；
5. 不同会话可以并发，切换当前 UI 会话不能暂停其他会话；
6. 权限弹窗必须携带所属会话，后台会话的权限请求不能被当前会话误处理。

## 5. Tao Runtime 事件边界

React 只订阅 Tao 的 `tao-runtime-event`，不直接绑定 Pi 的 JSONL 协议。

当前事件至少覆盖：

- `runtime`：启动、状态、保存、连接；
- `session`：会话准备和恢复；
- `turn`：开始、完成、中止；
- `message`：思考增量及按稳定文本块 ID 的 `text_block_delta`/`text_block_end`，阶段为 pending/commentary/answer；
- `tool`：工具开始、更新、结束；
- `context`：上下文整理、压缩及首份记录保存/失败通知（不携带完整内容）；
- `retry`：自动重试；
- `queue`：steer/follow-up 队列；
- `permission`：询问、允许、拒绝；
- `trace`：工作过程节点；
- `metric`：ready、首次输出、完成耗时；
- `error`：产品级错误。

跨 Node、Rust、React 允许传递的内容必须是产品级摘要：

- 工具名称；
- 动作类型；
- 脱敏后的相对目标路径；
- 截断后的命令预览；
- 状态和耗时；
- 用户需要做出的权限决定。

聊天和工作过程事件禁止跨边界传递：

- API key；
- 完整系统提示词；
- 原始工具参数；
- 文件正文；
- stdout/stderr；
- 完整工具结果；
- 原始 Pi 事件 JSON；
- Provider 网关完整响应。

定制页的主动工具测试是独立请求，可以返回受大小限制的执行结果供用户检查，不进入聊天或工作过程事件。

上下文预览与快照也是主动读取接口：仅经独立命令返回经过白名单筛选、大小限制和常见凭据遮盖的系统指令/工具定义。消息事件只发送快照状态通知。快照捕获标准 SDK 输入，不保存历史正文、隐藏推理、工具结果、请求选项或请求头；不等同于供应商最终 HTTP 请求。

## 6. 提示词、工具和 Skills 的装配

当前 Tao 定制配置保存于：

```text
%USERPROFILE%\.tao\agents\catalog.json
```

当前支持：

- 系统提示词追加；
- 系统提示词替换；
- 会话附加提示词；
- 内置工具组合；
- 共享工具库中的程序、Shell 和 HTTP 工具；
- Tao Skills 开关。

旧 `runtime/profile.json` 首次读取时迁移并保留。组合保存工具 ID 引用，创建会话时展开为快照；项目默认优先于全局默认。编辑组合不改变已有快照、不重启 Runtime，空闲会话可明确选择组合或应用新版。

工具库权限与组合权限共同生效；显式禁止、文件工作区范围优先于完全放行，工具库要求询问时不能被组合放宽。具体操作见 [智能体组合与工具使用](./10-智能体组合与工具使用.md)。

`runtime/prompt-policy.mjs` 定义 `tao-context-v2` 的平台执行规则、角色相关协作规则、工具短用途、默认成员解析及按需文档入口；`runtime/context.mjs` 管理共享组装、环境块、模板和初始记录。替换只改变身份与角色，不移除实际工具指导及平台规则。完整工具 description/Schema 通过 tools 提供，不重复注入 system；`read_tao_doc` 仅按固定专题读取随包手册正文，按需进入工具结果，仍遵守权限。

模板复用内核纯提示词组装器，用占位符表示动态环境；实际权限/时间在每轮 `before_agent_start` 时绑定。首份记录在 `Agent.streamFunction` 委托给供应商前捕获经过上下文转换的标准输入，既有记录不覆盖。`SYSTEM.md`、Skills 和扩展仍按内核资源机制生效。

新组合默认开启委派；开启且允许组合列表为空时解析为继承当前配置的单一默认成员，不开放整个组合库。首次实际协作调用才建立协调器。旧组合和会话的关闭值与缺省禁用保持不变；父子工具/权限交集、层级和预算约束仍执行。

Skills 统一放在：

```text
%USERPROFILE%\.tao\skills
```

不要要求用户再维护一个 Pi 产品目录。Runtime 使用 Pi 的资源加载能力，把 Tao 目录作为额外 Skill 路径。

## 7. 权限和沙盒的边界

Tao 当前有权限审计：

```text
Pi tool call / user bash
  -> Tao 规则判断
  -> 自动允许 / 询问 / 拒绝
  -> 继续执行或返回阻止结果
```

权限审计决定是否允许动作，执行后端决定运行位置。当前支持本机与可选的本机 Docker Linux 容器后端：内置命令、自定义程序/命令共用执行接口，Docker 文件工具在挂载工作区中操作；HTTP 工具由宿主受控代理检查网络、主机和凭据规则。显式边界不受 full_access 覆盖，成员能力与父组合取交集。

Docker 不可用时拒绝执行，不回退本机。任意扩展仍是可信宿主代码，受限组合禁止加载；Windows 原生隔离、VM、逐成员独立副本和任意进程的域名代理尚未接入。配置、运行参数与验收范围见 [权限执行沙盒与压缩策略](./13-权限执行沙盒与压缩策略.md)。

## 8. 会话事实源

Pi session JSONL 是 Agent 上下文和消息事实源。Tao 当前还保存 `conversation.json`，用于快速加载 UI 和产品元数据，这是第一阶段过渡投影。

后续修改会话存储时，不能在 Tao 中再造一套与 Pi 不一致的会话树或压缩逻辑。

## 9. 顶层禁止事项

后续开发默认禁止：

- 在 Tao 重写 Agent loop；
- 根据问题内容动态猜测或开关工具；
- 在 Tao 实现第二套重试；
- 在 Tao 实现第二套上下文压缩；
- 把 `.tao` 当成 Agent 工作区；
- 把工作区路径保护误称为沙盒；
- 让发布版回退到开发机路径；
- 把发布生成资源提交进源码；
- 让一个会话启动两个独立 prompt；
- 依赖当前激活会话推断后台事件归属。

内核代码可按产品需要修改；公开接口和 Extension 机制优先复用。改动需记录源码位置、原因、原始版本和验证结果，保持提交及发布资源可追踪。

# Tao 安装部署与项目迁移

## 1. 两种完全不同的迁移目标

迁移前先确定目标：

| 目标 | 应该复制什么 |
|---|---|
| 给普通用户使用 | 直接分发 MSI，不复制 Tao 源码 |
| 换电脑继续开发 | 复制 Tao 源码和必要的 Pi 源码，重新安装开发环境 |
| 只备份源码 | 保留源码和文档，排除可再生依赖和构建缓存 |
| 迁移历史配置和会话 | 额外复制 `%USERPROFILE%\.tao`，并检查工作区路径 |

安装软件和复制源码不是同一件事。普通用户不应该通过压缩项目目录来安装 Tao。

## 2. 普通用户安装

使用发布目录中的 MSI：

```text
src-tauri/target/x86_64-pc-windows-msvc/release/bundle/msi/
Tao_0.1.0_x64_en-US.msi
```

安装后：

- Tao 程序和内置 Runtime 位于安装目录；
- 配置、认证、Skills 和会话位于当前用户的 `%USERPROFILE%\.tao`；
- 卸载或升级软件时，不应默认把用户 `.tao` 当作安装文件覆盖。

目标电脑不需要 Tao 源码和 Node.js。模型是否可用取决于 Provider 网关、API Key 和网络。

## 3. 换电脑继续开发

在旧电脑上可以先关闭 Tao、Vite 和 Rust 编译进程，然后执行：

```powershell
cd <Tao 项目根目录>
cargo clean --manifest-path src-tauri/Cargo.toml
```

这只清理 `src-tauri/target`。然后再压缩或复制 Tao 项目目录。

新电脑上需要重新具备：

- Node.js/npm；
- Rust stable；
- MSVC C++ 构建工具；
- WebView2；
- Tao 根目录依赖；
- Pi 副本依赖。

复制完成后：

```powershell
cd <Tao 项目根目录>
npm.cmd install

cd vendor/pi
npm.cmd install --ignore-scripts

cd ..\..
npm.cmd run check
npm.cmd run tauri dev
```

## 4. 为了减小源码压缩包可以排除什么

下列目录都是生成物、缓存或可以重新安装的依赖，通常可以从“源码备份包”中排除：

```text
node_modules/
vendor/pi/node_modules/
dist/
src-tauri/target/
src-tauri/resources/
.tao-release-cache/
```

其中：

- `node_modules/`：Tao 前端依赖；
- `vendor/pi/node_modules/`：Pi 运行依赖；
- `dist/`：Vite 前端构建结果；
- `src-tauri/target/`：Rust 编译缓存和产物；
- `src-tauri/resources/`：发布准备脚本生成的 Node、Pi 和 Runtime 资源；
- `.tao-release-cache/`：Node 压缩包和解压缓存。

排除这些目录后，新电脑需要重新执行依赖安装和发布准备。

## 5. 源码备份包必须保留什么

至少保留：

```text
src/
src-tauri/
scripts/
docs/
vendor/pi/                 # Pi 源码副本
package.json
package-lock.json
vendor/pi/package.json
vendor/pi/package-lock.json
tsconfig.json
vite.config.ts
README.md
```

如果后续要直接在新电脑生成安装包，还必须保留 `vendor/pi` 源码，不能只保留 Tao 的前端和 Rust。

## 6. 是否迁移 `.tao`

`.tao` 不在 Tao 项目目录中，而在：

```text
C:\Users\<用户名>\.tao
```

如果只想在新电脑重新配置模型、不保留历史记录，可以不迁移 `.tao`。Tao 启动时会重新创建目录，之后重新配置 Provider、模型和 API Key。

如果要保留数据，需要复制：

```text
%USERPROFILE%\.tao
```

但要注意：

- `auth.json` 包含 API Key，复制和备份时要保护；
- 会话里的 `workspacePath` 是旧电脑的绝对路径；
- 换电脑后这些路径可能不存在，需要在 Tao 中重新选择工作区；
- 不要把 `.tao` 放入源码仓库或发布资源；
- 不要把 `.tao` 和 MSI 一起公开分发。

## 7. 不要混淆的目录

| 目录 | 作用 | 是否随源码发布 |
|---|---|---|
| `vendor/pi` | Tao 使用的 Pi 源码副本 | 开发源码需要保留，正式安装包由脚本复制 |
| `src-tauri/resources` | 发布资源暂存目录 | 不需要提交，重新发布会生成 |
| `src-tauri/target` | Rust 构建目录 | 不需要复制 |
| `node_modules` | Tao 依赖 | 可重新安装 |
| `vendor/pi/node_modules` | Pi 依赖 | 可重新安装 |
| `.tao-release-cache` | Node 发布缓存 | 可重新生成 |
| `%USERPROFILE%\.tao` | 用户配置、认证、会话 | 是否迁移由用户决定 |

## 8. 迁移后的检查

源码迁移后先执行：

```powershell
npm.cmd run check
```

再启动：

```powershell
npm.cmd run tauri dev
```

如果要重新发布：

```powershell
npm.cmd run tao:release
```

不要因为源码压缩包变小，就误以为它已经是可安装软件。可安装软件仍然必须通过 MSI 发布流程生成。

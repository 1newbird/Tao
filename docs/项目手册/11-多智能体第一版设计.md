# Tao 多智能体第一版设计

日期：2026-10-16。状态：父子委派、同级通信、接续任务、共享任务板、依赖与有界重试已接入源码，自动回归与桌面验收分别记录在开发 TODO。开发基线为 `952f194`（组合、工具权限、定制 UI 与设计文档）。

## 1. 实现目标

在现有组合基础上，让主智能体把任务委派给有独立上下文的子智能体，并获得进度和结果。先做可验证的委派链路，再扩展同一任务树内的通信与后续任务；具体业务工作流仍单独设计。

借鉴开源实现的工具入口划分：创建、通信、等待、查询与中断分别定义接口。参考 [Codex 多智能体工具规格](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_spec.rs)，采用 Tao 自己的任务状态与权限模型。

1. 第一步已接入：父子执行闭环、只读任务状态、隔离/权限/停止与持久记录。
2. 第二步已接入：成员定向通信、显式追加任务、状态事件与主邮箱消息唤醒等待。
3. 第三步已接入：共享任务、成员预领、验收依赖、版本比较、单任务取消和有界重试/重分配；单 Runtime 执行所有权与时限绑定到具体尝试。跨进程租约和跨根请求的常驻成员仍待后续。

Agent、Task、Attempt、Message 使用不同 ID。Agent 表达执行者及其私有会话；Task 保存任务说明、负责人和验收状态；Attempt 保存执行代次与结果。一次成功运行先进入 submitted，父代理可以验收为 accepted 或拒绝为 rejected。Agent 空闲和任务通过验收不是同一状态。一个成员现在可以先后处理多个任务：复用 agentId 和私有会话历史，新建 Task/Attempt；每个成员同时最多执行一个任务。

第一步以单 Node 进程内的协调器调度独立 Session，父代理等待不占子代理执行配额。任务记录保存到 Tao 数据目录，Runtime 重启将未结束的执行标记 interrupted，不自动重复调用模型或工具。临时中断不能撤销已生效的文件/外部系统操作。

Message 由协调器填写真实来源，普通消息只提供信息，不赋予工具权限或取消同级任务的权力。消息先持久化，再在下一次模型调用前进入接收方私有上下文；普通发送不启动新轮次，空闲成员等待显式后续任务。

- `agents.rs`：组合目录、配置校验、版本和实际配置快照。
- `tao-runtime.mjs`：单 Runtime、多 `AgentSession`、独立 cwd、模型和上下文，已有会话创建与取消入口。
- `policy.mjs`：显式禁止、询问、文件工作区范围及工具库权限。
- Node → Rust → React：已有 conversation/request 路由、权限请求与 Trace 展示。
- `test:agents`：本地模拟模型服务、并发会话、工具和取消回归，可扩展测试。

现已在多会话之上接入主子关系、委派工具、共享任务树、定向邮箱、接续任务、依赖、重分配与持久记录。成员的认领是预领下一项，当前任务退出后才执行；没有常驻成员自动轮询模型。

## 3. 第一条交付链路

```text
用户在组合中启用委派能力
  → 主智能体调用 spawn_agent
  → 校验组合、所属任务树、权限上限与数量限制
  → 捕获子代理配置快照，创建独立 AgentSession
  → 返回 agentId，主智能体可以继续工作
  → wait_agent / get_agent_status 等待或读取状态与结果
  → 主智能体根据真实结果汇总回答
```

当前新组合默认开启委派；旧组合/会话保留已保存值，缺少配置的旧数据仍关闭。开启但允许列表为空时，Runtime 仅注册继承当前配置的“默认成员”，不会允许任意组合；指定列表后只允许所选组合。普通工具页不需要逐项勾选协作工具，显式工具权限仍执行。首次协作调用才建立本轮记录，普通问答不产生空团队。

预算默认值：子任务并发 3、单轮最多 8 项任务（含未认领任务和接续任务）、层级 1、每次尝试 10 分钟/32 个模型轮次。在“定制 → 组合设置 → 子代理协作”可设置并发 1–4、任务总数 1–32、每次尝试时长 1–1200 秒和轮次 1–100。每任务最多三次尝试，本轮累计最多 32 个成员。默认成员仍受权限交集限制、不递归委派，未启用的旧组合不会装配协作工具。

子代理默认只接收任务描述和明确提供的上下文，不自动复制整段主会话历史。每个子代理保留组合版本、实际工具定义、模型、工作区、父任务与根会话引用。

主会话的允许组合列表来自会话快照；每轮请求开始时解析这些目标组合并冻结实际版本，子任务从本轮捕获的配置创建。编辑组合不会改变运行中的任务。目标组合设置了默认模型时使用该模型，否则继承当前主会话模型。父代理等待结果不占子任务并发名额。

## 4. 工具接口

| 接口 | 输入要点 | 行为与返回 |
|---|---|---|
| `spawn_agent` | taskName、description、profileId | 返回 agentId、taskId、attemptId 与 queued 状态，后台执行 |
| `get_agent_status` | 一个或多个 agentId | 主代理读取当前成员和所有已登记 Task/Attempt 的状态、候选结果或错误，不启动任务 |
| `wait_agent` | agentIds、mode、timeoutMs、afterSequence | 主代理等待成员任务或自己的邮箱消息；any 等一个新终态，all 包含等待期间新认领的任务；省略 agentIds 包含未认领及阻塞项；检查 finished/reason/messages，超时 0–60 秒不取消任务 |
| `cancel_agent` | agentId | 主代理停止成员及排队任务，等待确认；成员只能停止自己，返回停止请求后结束执行，不能等待自身执行 Promise |
| `review_agent_task` | taskId、decision、expectedVersion、attemptId | 父代理核实证据后 accepted/rejected；只允许验收当前版本/尝试的 submitted 结果 |
| `list_agents` | 无 | 查看自身/父级标识与同树精简名册；不返回同级私有上下文或结果 |
| `send_message` | recipient、body、kind、requestKey、可选 replyTo | 同树定向投递；recipient=parent 联系主代理；重试复用请求键，不隐式启动空闲代理 |
| `read_agent_messages` | 可选 afterSequence、limit、includeDelivered | 读取自己的邮箱；可重新读取已投递记录，不能指定他人的邮箱 |
| `followup_task` | agentId、taskName、description、requestKey | 仅主代理可调用；新建任务并复用私有历史，成员忙时排队，不打断当前任务；重试复用请求键 |
| `create_task` | taskName、description、requestKey、dependsOn，可选 eligibleProfileIds | 主代理登记共享说明；无依赖也须显式传 []；回执返回实际依赖与获准组合 |
| `list_tasks` | 无 | 主代理和成员查看共享任务说明、版本、依赖与负责人；不含其他任务的私有说明或结果 |
| `claim_task` | taskId、expectedVersion | 成员原子认领给自己，创建新 Attempt 并排在当前任务后；每人最多预领一项 |
| `assign_task` | taskId、expectedVersion、requestKey，agentId/profileId 二选一 | 主代理分配可执行任务；agentId 复用成员历史，profileId 创建独立新成员 |
| `cancel_task` | taskId、expectedVersion、requestKey | 主代理取消单个未结束任务，等待执行清理；保留该成员其他排队任务 |
| `retry_agent_task` | taskId、expectedVersion、requestKey、reason、acknowledgeSideEffects，agentId/profileId 二选一 | 主代理重试失败/拒绝/取消/中断任务，增加 generation，保留 taskId 及全部旧 Attempt |

以上接口均已接入。成员获得名册/发送/邮箱/停止自身和任务板查看/认领六项协作工具，没有创建成员、给他人分配、重试或验收权限。status/wait 返回状态快照；any 模式带回上次的 sequence 作为 afterSequence，避免同一终态反复唤醒。等待收到主邮箱消息时可提前返回，不表示成员完成。查询结果不包含完整工具配置或凭据，文本结果超过 8000 字符会明确标记截断。

### 共享任务、依赖与重试

- 创建共享任务时先保存 Task，不创建空 Agent/Attempt。无未验收依赖时为 pending，否则为 blocked；只有全部前置任务 accepted 才转为 pending。submitted、rejected、failed 均不会解除阻塞。
- dependsOn 为必填参数，无依赖也须传 []；遗漏或类型错误在创建前拒绝，不生成残缺任务。说明中提到前置任务不会自动建立依赖，创建后应核对回执中的 dependsOn、eligibleProfileIds 和 state。
- 依赖只能引用本轮已经存在的任务，创建后固定，因此不能形成自依赖或依赖环。前置失败或被取消后，下游保持 blocked，主代理决定修复前置或取消下游，不静默跳过依赖。
- 成员通过 list_tasks 判断可认领任务，claim_task 必须携带最新 version。版本比较、负责人设置和保存之间没有 await，竞争同一版本只有一个成功；其他成员重新读取任务板。每位成员一次最多预领一项，当前任务结束后才开始执行，不能等待自己尚未启动的任务。
- assign_task 显式启动新成员或复用已有成员；忙时排队，空闲成员不会因为任务板变化或普通消息自行调用模型。依赖解除也只改变可认领状态，不自动派发。
- 共享任务说明对同树成员可见；普通 spawn/followup 的私有说明及其他成员结果不出现在任务板。依赖结果由主代理核实后，通过任务说明或定向消息提供需要的证据，不自动复制私有上下文。
- 每次状态或所有权变化增加 version；验收同时绑定 attemptId，旧版本、旧尝试和旧工具入口均不能修改新一代状态或获得新的工具授权。
- 只有 failed/rejected/cancelled/interrupted 可以重试。submitted 须先验收，accepted 不能重开；需要追加工作时新建任务。运行中先 cancel_task 并等待清理，不能仅因时限到了就把执行权交给别人。
- 重试明确填写 reason 和 acknowledgeSideEffects=true，先检查现有文件/外部状态；Runtime 将修正原因交给新尝试。此确认不保证外部服务幂等，已有操作不会回滚，也不自动重放旧工具调用或权限确认。
- 重试保留 Task ID，创建新 Attempt ID 并递增 generation，每 Task 最多三次。共享任务可在 eligibleProfileIds 范围内重新分配；普通 spawn/followup 的重试保持原组合。复用 agentId 会保留私有历史，profileId 会创建没有旧成员历史的新上下文。
- create/assign/cancel/retry/followup 使用本轮根请求键去重；重试同一操作须复用完整原参数，返回原操作回执，不另建执行尝试。
- 运行记录保存 ownerAgentId、attemptId、generation、expiresAt 和 releasedAt。这里的 lease 表达单 Runtime 内的执行所有权与时限；不支持其他进程抢占或超时自动重派。超时先中止适配器并等待工具和会话清理，再释放名额；旧回调不能覆盖新尝试。

主代理等待所有任务时也包含未认领和 blocked 项；这些项不会被误报为执行结束。需要先验收前置结果时使用 any 加事件游标，或查询状态后验收，避免只等 all 而不解除依赖。

### 邮箱与接续任务边界

- 消息类型为 finding/question/suggestion/reply/cancel_request/notice；取消建议需要主代理判断后另调控制工具。
- 运行时绑定来源成员、来源 Task/Attempt 和接收方当前 Task；模型不能填写来源身份。已结束尝试不能再发消息。
- 每条消息最多 4000 字符，每树最多 128 条、每个发送者最多 32 条、每个接收方最多 32 条未投递消息。读取默认 16 条，最多 32 条。
- 请求键在来源尝试内去重；相同键和内容返回原消息 ID，改内容复用键则拒绝。接续任务请求键由主代理在本轮内去重。
- 邮箱分页返回 sequence（最后一条返回消息的游标）、hasMore 和 stateSequence（任务树事件位置）；继续翻页使用 sequence，不能用 stateSequence 跳过尚未返回的消息。
- queued 表示落盘入箱；delivered 表示进入模型上下文或邮箱工具结果，不表示模型已处理或业务动作完成。未能投递即结束的消息标为 undelivered。
- 接收方执行模型/工具时不被普通消息打断，在下一模型调用前投递；权限等待期间不绕过确认。空闲时只入箱，显式接续任务才继续模型调用。
- 接续任务计入同一 maxTasks 上限、复用冻结的配置和模型；成员内串行，不放宽并发。取消成员同时取消排队任务，已取消成员不复活；需要另建成员。
- 历史任务与验收状态保留。迟到回调绑定旧 Task/Attempt，不能改写后续任务；每个任务只返回自己的新输出，不能把旧答案当作新结果。

## 5. 权限与状态约束

- **身份**：agentId 由 Runtime 分配，目标必须属于当前根任务树；模型不能伪造父任务或访问其他会话的代理。
- **授权上限**：子代理的工具及执行权限受到父任务和用户授权约束。第一版采用保守交集；显式禁止、询问和工作区范围不能被子组合放宽。
- **工具定义**：自定义工具比较稳定 ID 和实际定义，避免同名工具或新定义通过继承获得旧授权。
- **资源加载**：Skill 开关取父子交集；第一版子代理不加载 Extension，直到扩展具备可声明和可约束的能力边界，防止其另行注册工具绕过交集。
- **工作区**：默认继承父任务工作区，第一版不允许模型任意选择其他目录；多个代理共用同一目录时仍可能写冲突，先通过权限和任务分工限制，后续再引入隔离执行。
- **权限弹窗**：归属根会话，同时显示真实子任务名称；确认只应用于明确的任务和工具范围。
- **结果隔离**：子代理输出进入自己的上下文，最终结果作为工具结果交给主代理；不会混入主会话正文流或其他会话。
- **取消传播**：停止主请求、删除根会话、关闭 Runtime 会取消所属子任务与权限等待。准备期间也必须响应取消；无法确认时明确记录失败并执行现有停止兜底。
- **父任务结束**：第一版结束前回收未完成子任务，避免产生无人管理的后台任务；后台持续代理后续另行设计。
- **用量**：先记录模型调用与用量，限制数量、层级和执行时长。后续令牌预算通过用量事件收敛，不宣称能撤销已经消耗的调用。

执行尝试：`queued → preparing → running ↔ waiting_permission → submitted/failed/cancelled/interrupted`，停止确认期间为 cancelling。Task 在 submitted 后可转 accepted/rejected；提交不等于验收。执行适配器完成清理后才释放并发名额。模型调用用量按收到的用量事件记录，不构成硬令牌预算保证。

协调器在 `%USERPROFILE%/.tao/teams/<conversationId>/<runId>.json` 保存任务、执行尝试与实际配置；子会话在同级 `<runId>/sessions/`，不混入普通会话列表。原子写入失败则停止派发。启动时将未结束的执行标记 interrupted，保留损坏记录并继续恢复其他记录；不会自动重试已发生的外部操作。删除主会话会一并删除该目录。

工作面板的 Trace 顶部增加只读“协作任务”概览，显示待认领、依赖阻塞、执行/提交/验收状态、版本和当前执行代次；根会话消息 Trace 只显示来源、目标、类型和投递状态，不展示正文或成员私有推理。接续任务保留旧行；同一任务重试更新当前行，全部旧尝试保留在本轮任务记录。候选结果通过工具交给主代理，不作为主会话的流式正文。桌面手工认领/拖动分配继续留待后续。

### 成员查看与人工介入（已接入源码，桌面验收单独追踪）

右侧“工作过程”的可折叠“协作成员”区域承载轮次选择和成员列表，点击后在中间区域按对话、执行记录、协作消息和任务历史查看；详情可返回主对话或打开独立窗口。主对话顶部不常驻成员栏；收起右栏不关闭详情，切换成员保留内存草稿及阅读位置。导航与详情共享一个查看状态，打开视图不创建执行者。Rust 的 `get_collaboration` 通过同一 Runtime 读取活跃协调器或历史记录；显式投影字段，不读取 Session JSONL，不返回配置、隐藏推理和工具原始参数/结果。可见 assistant 文本与工具名称/状态按容量限制保存到 `viewEvents`；老记录使用 Attempt 最终结果回看。列表显示最近 50 轮，摘要递增加载有上限和提示。

`open_member_window` 先验证所属轮次和成员，再按相同身份复用原生窗口；它只创建 Webview，不创建执行者或 Node Runtime。成员窗口只加载成员视图，不初始化主 App，会与主窗口共用同一后台。关闭查看页不会调用取消接口；返回主窗口会定位所属会话。

`control_collaboration` 使用受限结构化请求转发 `control_team`。用户补充说明创建 `from=user` 的消息并绑定目标 Task/Attempt，在模型边界或邮箱工具结果中投递；不会调用 steer 强行打断当前模型/工具，也不修改权限。目标尝试结束后未送达说明作废，不流入下一任务。追加任务显式新建 Task，复用成员 Session 历史。人工操作通知主代理邮箱，但普通消息不启动新模型轮次。

控制通过 runId、任务版本与 attemptId 校验，UI 请求键去重并合并运行中重复操作；根轮次结束后只接受原操作回执的查询，不启动新任务。停止任务、停止成员、停止整轮分别复用原协调器取消和根请求中止逻辑。草稿保存编辑时的目标，任务/版本变化后暂停发送，由用户明确确认重新绑定。标签切换保留当前查看工作区内的草稿和阅读位置，草稿不落盘。

## 6. 实施拆分

1. 提取独立协调器与可注入执行适配器；先测试状态、并发、层级、任务树归属和取消。
2. 装配协作工具和独立子会话，捕获配置快照，落实权限交集。
3. 将子任务状态与权限路由到根会话；工作过程提供可折叠记录，保留真实归属。
4. 已接入有界邮箱、后续任务和主邮箱消息唤醒；不通过模型空轮询派发任务。
5. 第一条链路已包含任务元数据、异常中断标记、删除和关闭清理；后续任务恢复执行及 Provider 生命周期继续完善。
6. 执行本地模拟回归、真实桌面验收和发布资源验证。

## 7. 验收用例

- 两个子代理并发使用不同组合及独立上下文；结果只交给所属父任务。
- 新建子任务捕获配置版本，已有子任务不受组合编辑影响。
- 禁止工具、工作区外目标和改变后的自定义工具定义无法通过继承放宽权限。
- 父子权限请求显示正确任务名称，取消权限等待不会留存可执行的旧请求。
- 在准备、模型调用、工具执行、等待结果和消息投递期间取消，任务最终状态一致。
- 达到并发、层级、任务数量或时长限制时明确拒绝或排队，异常后名额可回收。
- any/all 等待语义明确，any 配合通知游标避免重复唤醒，status/all 可重复读取快照。
- 外来任务 ID、跨会话通信、重复后续任务和过量邮箱消息被拒绝。
- 主任务完成/停止后不遗留执行，关闭重开不会自动重复之前的工具动作。
- 未启用委派的旧组合、普通对话、重试和安装版启动保持兼容。

本设计把权限交集与资源归属作为第一步。上下文压缩策略、OS 沙盒、工作流编辑器和独立代理进程分别在后续批次实现。

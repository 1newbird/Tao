# Tao 开发环境与本地运行

> 第一次从零配置环境时，优先阅读 [03a-从零开始配置开发环境.md](./03a-从零开始配置开发环境.md)。

## 1. 开发命令在哪个目录执行

所有 Tao 命令从项目根目录执行：

```powershell
cd <Tao 项目根目录>
```

不需要先进入：

- `src-tauri`
- `src`
- `vendor/pi`

只有安装 Pi 依赖时需要临时进入 `vendor/pi`。

## 2. 前置环境

开发机建议具备：

- Windows x64；
- Node.js 和 npm，建议使用 Node.js 22 LTS；
- Rust stable；
- Visual Studio 或 Build Tools 的 MSVC C++ 工具链；
- Windows WebView2 Runtime；
- PowerShell；
- Git 可选，但 Files 的 Git 改动和 Diff 需要工作区安装并可调用 `git`。

Tao 根目录依赖和 Pi 副本依赖分开：

```text
Tao/node_modules
Tao/vendor/pi/node_modules
```

## 3. 第一次安装依赖

在 Tao 根目录安装 Tao 依赖：

```powershell
cd <Tao 项目根目录>
npm.cmd install
```

安装 Pi 副本依赖：

```powershell
cd <Tao 项目根目录>\vendor\pi
npm.cmd install --ignore-scripts
cd ..\..
```

如果出现以下文件不存在：

```text
vendor/pi/node_modules/tsx/dist/preflight.cjs
vendor/pi/node_modules/tsx/dist/loader.mjs
```

说明 Pi 依赖没有准备好，先重新执行上面的 Pi 安装命令。

## 4. 常用开发命令

### 类型和 Rust 检查

```powershell
cd <Tao 项目根目录>
npm.cmd run check
```

该命令执行：

- `tsc --noEmit`
- `cargo check --manifest-path src-tauri/Cargo.toml`

### 启动完整 Tauri 开发模式

```powershell
npm.cmd run tauri dev
```

Tauri 会根据 `src-tauri/tauri.conf.json` 先启动 Vite，再编译并启动 Rust 桌面应用。Vite 默认地址：

```text
http://localhost:1420
```

### 只启动前端

```powershell
npm.cmd run dev
```

这种方式只能查看 React/Vite 页面，不能验证 Rust command、Node Runtime、Pi 会话和文件系统能力。

### 构建前端

```powershell
npm.cmd run build
```

### 查看前端构建结果

```powershell
npm.cmd run preview
```

## 5. 开发模式实际运行链路

```text
Tauri Debug
  -> 系统 node.exe
  -> src-tauri/runtime/tao-runtime.mjs
  -> vendor/pi
  -> %USERPROFILE%\.tao
```

开发构建未选择工作区时，默认工作区是 Tao 仓库根目录，便于调试。发布构建未选择工作区时，默认使用当前 Windows 用户主目录，不会使用编译机源码路径。

## 6. `cargo clean` 的作用

可以执行：

```powershell
cargo clean --manifest-path src-tauri/Cargo.toml
```

它只清理 Rust 构建产物，主要包括：

```text
src-tauri/target/
```

不会删除：

- Tao 源码；
- `vendor/pi`；
- Tao 或 Pi 的 `node_modules`；
- `%USERPROFILE%\.tao`；
- Provider、API Key 和会话。

不要把 `cargo clean` 作为每次启动前的固定步骤。它会让下一次启动重新编译，适合释放磁盘空间、修复异常构建状态或准备源码备份。

## 7. 常见开发问题

### 端口 1420 已被占用

如果出现：

```text
Port 1420 is already in use
```

说明旧的 Vite/Tao 进程还在使用端口，不等于代码编译失败。先关闭旧开发进程，或在 PowerShell 中查找并结束占用该端口的进程，再重新执行：

```powershell
npm.cmd run tauri dev
```

### `tao.exe` 无法删除或拒绝访问

如果出现：

```text
failed to remove ...\tao.exe
拒绝访问。 (os error 5)
```

通常是旧的 Tao 进程仍在运行。先关闭窗口和旧的开发终端，再重试。不要在进程仍运行时反复清理 target。

### Runtime 启动失败

按顺序检查：

1. `node.exe` 是否能在命令行执行；
2. `vendor/pi/node_modules/tsx/dist/preflight.cjs` 是否存在；
3. `vendor/pi/node_modules/tsx/dist/loader.mjs` 是否存在；
4. `%USERPROFILE%\.tao` 是否可写；
5. Provider、Model 和 API Key 是否已经配置；
6. 是否误把发布资源路径问题带到了 Debug 模式。

## 8. 开发前后检查

最小检查组合：

```powershell
node.exe --check src-tauri\runtime\tao-runtime.mjs
npm.cmd run check
```

涉及发布资源或 Runtime 路径的改动，还要执行：

```powershell
npm.cmd run tao:prepare
```

然后检查 `src-tauri/resources` 中是否存在 Node、Runtime、Pi 和 `RELEASE-MANIFEST.json`。

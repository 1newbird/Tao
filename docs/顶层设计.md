# Tao 顶层设计

本文档是 Tao 的架构事实源。后续会话、功能、代码审查和发布验证均以本文档为准；与旧设计、临时实验或界面文案冲突时，以本文档为准。

完整路线见 [总纲与路线图.md](./总纲与路线图.md)，Pi 原生能力核对见 [Pi能力清单与映射.md](./Pi能力清单与映射.md)。

## 1. 产品定位

Tao 是一个以 Tauri 为桌面产品框架、以 Pi 为 Agent 引擎的应用。

```text
Tao = Tauri 产品壳 + Pi Agent 引擎 + Tao 产品界面与配置
```

Pi 不是 Tao 的外部依赖产品，而是 Tao 内部复用的 Agent 能力基础。Pi 已经实现的能力应优先直接复用，不在 Tao 中重新实现一套平行机制。

优先复用的 Pi 能力包括：

- Session 和会话树
- 上下文管理与记忆压缩
- Provider、Model 和 API 适配
- Agent 运行循环
- Skill、Extension 和 Prompt Template 加载
- RPC 事件和命令协议

Tao 负责产品体验，不负责复制 Pi 的内核能力：

- 中文桌面 UI 和交互
- 会话列表、设置界面和产品级导航
- Tao 数据目录和配置生命周期
- 后续的 Agent、Skill、Extension 管理界面
- 面向桌面用户的权限、通知和错误展示

## 2. 三层边界

```text
Tao UI
  └─ React + TypeScript

Tao 桥接层
  └─ Tauri + Rust
     ├─ 窗口和文件系统边界
     ├─ 单一 Tao Runtime 进程生命周期
     ├─ 前端事件转换
     └─ conversationId / requestId 路由

Pi 引擎
  └─ 共享 ModelRuntime + 多 AgentSession / SessionManager
```

Tao 生命周期内只维护一个常驻 Node Runtime。Runtime 共享 Pi 的 `ModelRuntime`、认证和模型配置；每个 Tao 会话拥有独立的 Pi `AgentSession`、Pi session 文件、运行状态和工作目录。多个会话显示相同 Runtime PID 是正常行为，不代表它们串行执行。

Tao 桥接层可以适配 Pi，但不应在桥接层重新实现 Pi 的会话树、压缩算法、模型调用和 Skill 解析。

## 3. Pi 源码和用户数据分离

Pi 的源码作为 Tao 的固定版本引擎，放在项目或发布资源中：

```text
<Tao 项目根目录>\vendor\pi
```

用户数据不写入源码目录，也不依赖外部 Pi 安装目录。正式目标是统一使用用户根目录下的 Tao Home：

```text
C:\Users\<用户名>\.tao
```

开发阶段可以通过 `PI_CODING_AGENT_DIR`、`PI_SESSION_DIR` 和 `--session-dir` 将 Pi 现有目录机制重定向到 Tao Home，不需要立即修改 Pi 核心源码。

## 4. Tao Home 目录

目标目录结构如下：

```text
.tao/
├─ tao.json            # Tao 产品设置
├─ settings.json       # Pi 默认 Provider 和 Model
├─ models.json         # Provider、模型和兼容接口配置
├─ auth.json           # Pi 原生 Provider 认证配置
├─ conversations/      # Tao 会话索引与过渡期消息投影
├─ sessions/           # Pi SessionManager 管理的 JSONL 会话
├─ skills/             # 用户级 Skill
├─ agents/             # Agent 配置和预设
├─ extensions/         # Pi Extension
├─ prompts/            # Prompt Template
├─ logs/               # Tao/Pi 运行日志
└─ cache/              # 可删除缓存
```

目录职责：

- `sessions/` 的对话内容、上下文、压缩信息和会话树由 Pi 管理。
- `tao.json` 与 Pi 的 `settings.json` 分开，避免 Tao UI 设置覆盖引擎配置。
- Tao 可以保存会话索引、标题等产品元数据，但不维护第二份完整消息历史。
- Skill、Agent、Extension 和 Prompt 的实际加载仍使用 Pi 机制。
- Provider 认证使用 Pi 原生 `auth.json` 格式，由 Tao 设置界面统一读写；前端不回读或展示 key 明文。
- 自定义接口写入 `models.json`，默认 Provider/Model 写入 `settings.json`，这些配置属于 `.tao` 全局状态，不属于某个会话。
- 思考模式默认值写入 Pi 的 `defaultThinkingLevel`，会话运行时仍通过 Pi RPC 控制。
- Tauri WebView 缓存、编译产物等运行时文件可以留在 Windows AppData，不属于 Tao 核心用户数据。

`.tao` 不是 Agent 的项目工作目录。每个 Conversation 持有自己的 `workspacePath`，创建或重建其 `AgentSession` 时作为 Pi `cwd` 传入。它是 Pi 相对文件路径和命令执行的基准；当前阶段并不把它假定为安全沙箱。

## 5. 会话事实源

Pi session JSONL 是会话内容的唯一事实源。Tao 读取和展示 Pi 数据，不复制 Pi 的会话逻辑。

目标流程：

```text
Tao 新建会话
  -> 分配 Tao 会话 ID 或 Pi session ID
  -> Pi SessionManager 创建 session
  -> Tao 通过 RPC get_messages/get_entries 展示内容
  -> 新消息通过 RPC prompt 写入 Pi session
```

当前版本为了快速完成 UI，还保留了 `conversation.json` 消息投影。它是过渡结构，后续应收敛为只保存标题、时间、模型和 session 引用等元数据。

生成控制直接使用 Pi RPC，不在 Tao 中另建队列：

```text
停止生成       -> abort
当前轮追加调整 -> steer
当前回答后继续 -> follow_up
队列状态       <- queue_update
```

中止产生的 assistant 消息保留已有文本，并以 `stopReason: aborted` 映射为 Tao 的“已停止”状态。这样用户可以接着补充，而不丢失已生成内容和 Pi session 上下文。

启动恢复时以 Pi session JSONL 对账 Tao 投影，补回异常关闭期间已经落盘的 aborted/error 结果；空的 aborted 也保留为可继续的状态提示。

## 6. 扩展原则

新增能力前先检查 Pi 是否已经提供对应机制：

1. Pi 已有能力：通过配置、RPC 或 Extension 复用。
2. Pi 有底层接口但没有产品 UI：在 Tao 中增加 UI 和桥接，不复制底层逻辑。
3. Pi 确实缺少能力：优先设计为 Pi Extension 或 Pi 内核的可复用改动，再由 Tao 接入。

不应在 Tao 中创建与 Pi 平行的：

- 第二套会话树
- 第二套上下文压缩
- 第二套 Skill 解析器
- 第二套 Provider 调用层
- 第二套 Agent 运行循环

第一阶段还明确禁止：

- 根据消息内容判断是否需要 `read`、`bash` 或其他工具。
- 向 `createAgentSessionFromServices` 传入 `tools`、`noTools` 或 `excludeTools`，或在运行时开关工具。
- 自定义工具 allowlist / denylist，或用临时工具注入改变 Pi 默认行为。
- 重新实现模型重试、上下文管理或压缩。
- 解析 Pi TUI 文本来驱动图形界面。
- 将 `event.args`、`event.result`、`event.partialResult`、文件正文、命令 stdout 或完整工具 JSON 跨 Node → Rust → React 传递。

Pi 当前 SDK 在未显式覆盖工具参数时，按自身设置决定初始工具；若未配置 `defaultTools`，默认内置集合为 `read`、`bash`、`edit`、`write`。Pi 源码中存在的其他工具不等于 Tao 有权临时注入它们。

用户输入的标准路径：

```text
用户消息
  → Tao 调用对应 AgentSession.prompt()
  → Pi 自行决定是否调用默认工具并完成 loop
  → Tao 订阅 Pi 事件
  → Tao 归约为产品级 UI 状态、思考和正文
```

Runtime 可以订阅 Pi 的 `agent_*`、`turn_*`、`message_*`、`tool_execution_*`、`compaction_*`、`auto_retry_*` 和 `queue_update` 事件，但跨 Node → Rust → React 的稳定事件信封只允许：

```text
version, category, event, conversationId, requestId, text, elapsedMs
```

工具事件只被归约为当前一条可读状态，例如“正在读取 `src/App.tsx`”“正在执行命令”“正在修改 `src/App.tsx`”。读取路径仅用于生成短状态；聊天区和右侧检查器均不得成为工具日志或原始结果面板。

并发路由约束：

- 每次普通 `prompt` 有唯一 `requestId`；所有流事件按 `conversationId + requestId` 路由。
- 同一会话存在活动 prompt 时，不得启动第二个独立 prompt；新增输入只能调用 Pi 的 `steer` 或 `followUp`。
- 空闲会话上的 `steer` / `followUp` 必须明确拒绝，不能静默变成“追加消息”。
- 不同会话可以并发；切换会话或停止一个会话不得影响其他会话。
- Rust 的 Runtime 请求等待表必须以 Runtime 命令 ID 分发；Node 事件不能依据当前激活 UI 会话推断归属。

Pi 是唯一的自动重试实现者。Runtime 仅通过 Pi 的 `SettingsManager.inMemory()` 提供不写回用户配置的超时保护，并把 Pi 自动重试事件归约为“模型响应较慢，正在重试”等产品状态；Tao 不得再实现第二套网络重试 loop。

## 7. 演进顺序

详细路线以 [总纲与路线图.md](./总纲与路线图.md) 为准。下面保留当前已完成能力和长期方向摘要。

### 第一阶段

- Tauri 前端到 Pi RPC 的 vertical slice
- 一个常驻 Node Runtime 托管多个独立 Pi AgentSession
- 流式思考和回答
- 归约后的当前状态与可折叠执行摘要（连接、思考、工具动作、压缩、重试、完成、停止、错误）
- 基础模型配置和连接测试
- 停止、追加调整和回答后继续
- 全局模型与认证配置落盘
- 每会话独立工作区
- 会话删除和置顶

### 第二阶段

- 使用 Pi SessionManager 作为唯一会话事实源
- Tao 会话列表改为元数据索引
- 接入 Skill、Agent、Extension 管理

### 后续阶段

- 工具执行授权与权限 UI
- Agent 预设与工作流
- 会话树、分支和导入导出
- 对 Pi 引擎的必要定制，并保持改动可复用

## 8. 顶层决策

- Tao 是产品，Pi 是引擎。
- `.tao` 是 Tao 用户数据根目录，`.pi` 不应出现在用户产品体验中。
- Pi 的已有能力优先复用，避免重复造轮子。
- Pi session 是对话内容的事实源。
- 模型与认证是 `.tao` 全局配置，不跟随单个会话保存。
- 生成控制和消息队列使用 Pi RPC 的原生能力。
- Tao 生命周期内只维护一个 Node Runtime；每个会话拥有独立 AgentSession 和运行状态，切换会话不阻塞其他会话。
- Tauri 负责桌面边界和产品体验，Pi 负责 Agent 内核能力。
- 在没有必要前，不修改 Pi 核心；需要扩展时优先使用 Pi 的公开接口和 Extension 机制。

### 8.1 定制 Agent 的产品边界

Tao 的定制能力属于 Tao 产品本身，不要求用户同时维护 Pi 的配置目录。Pi 作为 Agent 内核提供可复用的会话、工具、Skill 和 Extension 运行能力；Tao 负责把这些能力组织成可保存、可切换、可测试的产品配置。

第一阶段的定制配置统一保存在 `%USERPROFILE%\.tao\runtime\profile.json`，Skills 统一放在 `%USERPROFILE%\.tao\skills`。Runtime 创建 Pi `AgentSession` 时：

- 系统提示词可以追加到默认提示词，也可以替换默认提示词；
- 默认工具模式保留内置 Coding Agent 的工具选择；
- 自定义工具模式通过 Pi SDK 的 `tools` 选择内置工具；
- Tao 自定义工具通过 Pi SDK 的 `customTools` 注册；
- Skills 通过 `DefaultResourceLoader.additionalSkillPaths` 从 Tao 目录加载；
- Tao 权限审计仍通过 Runtime 的工具调用钩子统一生效；
- 自定义工具测试只返回脱敏后的测试结果，不把原始执行结果写入聊天消息。

第一阶段只开放提示词、内置工具选择、命令/HTTP 自定义工具和 Skills 开关。Extension Hook 编辑、Agent 组合套装、配置版本和沙盒后端后续单独设计，避免把任意脚本执行、权限策略和普通 Agent 配置混为一谈。

## 9. 工作区与项目分组

工作区是 Agent 的真实 `cwd`，不是 `.tao` 数据目录。每个 Conversation 持有自己的 `workspacePath`，Pi `AgentSession` 创建时使用该路径；`.tao` 只保存 Tao 配置、会话元数据和 Pi session 数据。未选择工作区时，开发构建使用 Tao 仓库根目录便于调试，发布构建使用当前 Windows 用户主目录，绝不使用编译机源码路径。

界面上，顶部会话标题下方显示当前工作区名称和完整路径，输入框左下角保留紧凑的目录选择入口。工作区名称是可编辑的显示名，物理路径保持不变。左侧会话栏按规范化后的工作区目录分组，同一目录下的会话归入同一项目组；尚未选择目录的会话归入“未选择工作区”。

新建会话默认继承当前活动会话的工作区，因此选择一次目录后，在同一项目中继续新建会话不需要重复选择。每个会话仍可以单独切换工作区，切换后立即移动到对应项目组。工作区分组只影响 Tao 的导航和 Pi `cwd`，不改变 Pi 的工具选择、Agent loop、权限和上下文管理。
